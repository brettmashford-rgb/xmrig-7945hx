# v0.0.60: two row tiles share B reconstruction

v059 is the offline baseline, 888491.13 tiles/s in its accepted controlled
comparison. This release is an offline experiment, with v059 row-major,
new order-only control and shared-B pair modes. No live miner is integrated.

Each shared-B warp handles two canonical row tiles at the same column axis.
It reconstructs/transposes four B words once per 32-K step and feeds two
independent A/accumulator sets. Each query retains its own 10x16 mathematics,
128-K transcript folds, digest, target comparison and queue index. This
halves B reconstruction per pair but doubles accumulator sets and may reduce
occupancy. It does not implement packed-row MMA or promise a speedup.

The traversal visits (row0,col0),(row1,col0),(row0,col1),(row1,col1), then the
next adjacent row pair. It retains a two-A-tile working set rather than
cycling through all 512 rows. shared_b_axes.h maps paired ordinals bijectively
to canonical row-major IDs. RowPairSearch uses an explicitly documented paired
ordinal cursor and returns canonical Hit.tile values for proof construction.
Existing FastPlan and NonceSearch defaults are unchanged; a separate dispatch
preparation type prevents accepting row-major query bindings by mistake.
Only even row-axis counts are supported; other domains fail before allocation.
Production has 512 row axes and the synthetic proof profile has sixteen.

Two new 24-argument entries include actual v059 as control. The order-only
kernel changes axis selection, keeping v059 per-tile work. The paired kernel
uses eight warps per CTA and up to sixteen queries per CTA, 24576 bytes shared
memory, no CTA barriers. First/last partial pairs handle odd starts and odd
counts without output for queries outside the window. The host grid includes
the extra partial pair for an odd first ordinal. Targets/trace/queue indices
remain window-local; status and snapshot identities use that same window.

Mapped queries are independently CPU-checked in the inherited lean decoder.
The reset/scanner/collector remain on one stream; every one of 28 guard
endpoints remains checked. Overflow retries retain mappings before cursor
credit; stale reset/scan work is drained and cannot credit an unfinished
window. Snapshot and allocation ownership remain per dispatch; B is shared
only within the warp's two queries, not across backend lifetimes.

Before timing, the rig checks all 8388608 traversal IDs for duplicates,
omissions and inverse consistency. Each new mode then compares four complete
4096-query windows against actual v059, reassembling canonical contiguous
subwindows (including odd starts, pair-boundary crossing, middle and end).
It checks eight independent CPU transcripts, eighteen target/queue cases,
a populated 67-query overflow and all 28 deliberate guard corruptions per
mode. Both modes must produce a fresh V3 proof starting at paired ordinal one
and explicitly return its nonzero canonical tile ID to the official CPU
verifier. Odd retained miss windows, stale rejection and allocation cleanup
also remain required. Totals: eight full windows, sixteen CPU samples, 36
target cases, 56 guard faults and two fresh official CPU verifier proofs.
All mapping/correctness/proof flags gate timing.

Three resident searches use one synthetic production nonce/target. Twenty-four
rounds cover all six mode orders four times. Each searches 65536 unique tiles
per mode per round in advance(4096) windows. The 65536-tile interval comprises
whole adjacent row-pair blocks, so all three modes cover the exact SAME
canonical tile set, not just equal tile counts. The host coverage invariant
is checked after each uninstrumented timing round. A separate diagnostic must
retain sixteen async resets, 32 launches, sixteen stream waits and sixteen
504-byte downloads (8064 bytes), zero uploads/context-wide waits for every
mode. Setup and JIT resource facts are separate. A greater than 3% median
elapsed reduction is required to prefer a new mode; no automatic live adoption.
Output: SHARED B COMPARISON, DRIVER COUNTS, KERNEL RESOURCES;
report: shared-B-comparison.json. Speeds are relative to v059.

116 targeted host tests pass. They include an exhaustive compiled-helper
bijection and same-timed-set check over 8388608 production tiles, Python/C++
map/inverse agreement, canonical v059 transcript reassembly, odd pair windows,
unchanged MMA/fold/emit code, ABI/no-CTA-barrier checks, foreign preparation
rejection, every guard, CPU-checked canonical hits, overflow retries, stale
reset/scan cleanup with no cursor credit, balanced timing and installer gates.
The NVRTC 12.9.86 compute_120 C++17 repeat PTX build is byte-identical. Hardware
correctness, JIT resources and speed of the new kernels remain pending rig run.

The installer verifies 28 dependency manifests/files through v059, requires
its completed winning comparison and existing completion/proof gates, and
reads the CPU library pin from installed verified v031 metadata. It downloads
readable own-source PTX; no toolkit or pip package is installed on the rig.
No pool connection, shares or wallet capture is used. Genuine independent
pool acceptance remains unproven. No private header/nonce/seed/proof is
published. All miner code is our own and fee-free. CPU XMRig, clocks, pools,
permanent service definitions and autostart stay unchanged. The launcher
schedules a 15-minute WildRig fallback before stopping pearl.service, bounds
execution/cleanup to thirteen minutes and explicitly restarts it on exit.
