# v0.0.58: cheaper packed B arithmetic on the v057 baseline

v057 is the validated offline winner: 859971.29 versus quad5 815327.38
tiles/s (+5.48%), with forty registers per thread, unchanged shared memory,
no local spill and equal driver calls/bytes. Its correctness/proof gates
passed. By user direction, this release continues offline development against
v057; v054 remains the last live-validated worker. No live run is added.

The next experiment specializes packed B reconstruction for the actual
production noise range. noise_uniform_range in virtual_tile_scan.cu generates
int(hash_byte & 63)-32, so every uniform byte is in [-32,31], for every seed.
The kernel still requires K=32768, rank=128 and fill=64. During the existing
per-tile shared-cache load, b_bias_byte adds 32, storing each byte in [0,63].
Global noise buffers and cache size/layout are unchanged.

Let a and b be biased bytes in [0,63]. The required B value is unchanged:
64+(a-32)-(b-32)=64+a-b, which lies in [1,127]. Thus for four packed bytes,
(a | 0x40404040)-b produces all four exact results. Every byte subtraction
is nonnegative, preventing cross-byte borrow; each result is at most 127,
preventing carry. This uses one OR and one subtraction per packed B word
instead of the general modulo-byte subtraction/high-bit restoration path.
The specialization is intentionally for the canonical six-bit generator,
not arbitrary int8 uniform data. No new restriction is placed on pool seeds.

The new b_quad_biased_scan entry includes the unchanged v057 control kernel.
It keeps v057's producer mapping/two-stage transpose, stride-five shared
cache (20480 bytes per CTA), eight query warps, original 32-K loop and
24-argument ABI. A loads, MMA order, transcript fold and hash/target/queue
tail are verbatim. Stream/reset/snapshot, all guards, CPU candidate checks,
resumable cursor, overflow and stale handling are retained. No early operand
carrying, grouping, extra allocations or live worker integration.

Host tests compile the actual bias and packed arithmetic helpers and cover
all 4096 valid byte pairs with contrasting neighboring bytes, all 64 bias
inputs, and 262144 complete B fragment comparisons (every lane, every K
step, both halves/column blocks, two datasets) against original cached_b_word.
The six-bit generator provenance is checked explicitly. 93 targeted host tests
pass, including existing backend/queue/cursor tests, actual v057 control
selection, new ABI/barriers/MMA/shuffle invariants, unchanged source tail,
stale cleanup, paired timing/order/interval validation and installer gates.
The repeat NVRTC 12.9.86 sm_120 build is byte-identical.

Before timing, the rig preflight compares four full 4096-query transcript
windows against v057 (first, row crossing, middle, end), eight CPU transcript
samples, eighteen target/queue cases, populated 67-query overflow, all 28
deliberate guard faults, a fresh candidate and V3 proof verified by the
installed official CPU verifier, retained odd miss windows, stale rejection
and allocation cleanup. Missing/failed gates prevent timing. New GPU
correctness and performance remain pending rig execution.

The paired benchmark uses one shared synthetic production nonce/target and
identical ranges for v057 and the new entry, both caches resident, 24
alternating-order rounds, 65536 unique tiles per mode per round, advance(4096).
Primary timing is uninstrumented; setup and JIT resources are separate. A
separate diagnostic requires sixteen stream resets, 32 launches, sixteen
stream waits, sixteen 504-byte downloads (8064 bytes), no host uploads or
context synchronizations. More than 3% median elapsed reduction is required
to prefer the new entry. Output: B BIAS COMPARISON, DRIVER COUNTS,
KERNEL RESOURCES, b-bias-comparison.json. Gains are relative to v057, not v054.

The installer verifies 26 dependency packages, requires the completed v057
winning benchmark, prior completed experiments and existing v054 lifecycle/
v052 proof gates. Old GPU checks are reused, not repeated. CPU library hash
is read from installed verified v031 metadata. No toolkit or pip dependency
is installed on the rig. No pool connection, shares or live worker changes.
Pool acceptance remains unproven. No private wallet, capture, header, nonce,
seed or proof is published; all miner sources are our own and fee-free.
CPU XMRig, clocks, pool settings, permanent services and autostart stay intact.
The launcher schedules a 15-minute WildRig fallback before stopping
pearl.service and explicitly restarts it on exit. No continuous miner is
installed.
