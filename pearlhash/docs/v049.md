# v0.0.49: bounded live integration of validated packed direct scanning

v048 passed the RTX 5060 correctness/proof gates and 24-round three-way rig
comparison. Medians: baseline resident 466836.58, packed resident 486168.97,
packed direct 495099.38 tiles/s. Packed direct improved throughput by 6.054%
(5.708% less elapsed time), above the 3% elapsed-time adoption threshold.
Separate 65536-tile diagnostics confirmed 400 to 16 DtoH calls, with all
original guards retained. These are controlled synthetic search timings,
not an overall live mining rate or pool acceptance result.

This release adds --packed-direct to the existing bounded live worker. It
selects new_snapshot_search(...,direct=True) with one stream and 4096-tile
windows; --cache-a is required. It is mutually exclusive with --resident-maps
and --two-streams. The GPU scanner/collector, maps, targets, A cache and v039
GPU B commitment are reused unchanged from their validated releases. No new
PTX or native build is needed. Existing default backend choices are retained.

The installer verifies 17 installed dependency manifests/files, reads the CPU
library pin from the verified v031 manifest, and requires completed v048
preflight: both variants, eight full transcript/descriptor windows, sixteen
independent CPU samples, 36 target cases, 56 deliberately corrupted guard
endpoints, both fresh official-verifier proofs, partial queues and stale-work
lifecycle. It also requires the packed-direct timing win, balanced 24-round
work total and exact measured upload/readback/launch diagnostics. Failed or
missing gates prevent downloads and pool connection. Old GPU tests are not
repeated. The pinned v048 readable PTX is reused in place on the rig.

One live connection runs for at most 300 receive seconds, with 15-second
heartbeats and progress/status reporting. Jobs use the actual pool target;
assigned extranonce as worker nonce remains a hypothesis. Complete returned
candidates undergo independent CPU math checks before fresh proof construction.
At most one fresh share is submitted, with no reconnect/retry. Accepted share
counts require the correlated submission verdict; report_info acknowledgements
are separately recorded. Worker/cache/context cleanup and joined worker status
are saved in mining-result.json. Backend tag: packed-direct-one-stream-v049;
terminal summary includes Packed direct windows.

58 host tests pass: new-path selection/direct=True, full-nonce rollover,
correlated verdict orchestration, status acknowledgement without an accepted
share, cleanup/join, incompatible flags before networking, installer gate
failures (including missing proofs/guards/stale checks, nonfinite timings and
wrong driver counts), plus packed snapshot/direct/resident/queue/planner tests.
Scripted pool tests use fake GPU/proofs and never establish genuine acceptance.
The v049 live run itself remains pending on the rig.

The existing find_login helper locates a locally saved independent-login capture.
No wallet, capture, private header, nonce, seed or proof is published. No miner
fee or third-party miner code. Pool endpoint stays pool.pearlhash.xyz:9000.
No permanent service, autostart, clock or CPU XMRig change. The Termius wrapper
schedules a 15-minute WildRig fallback before stopping pearl.service, bounds
the run to 13 minutes including cleanup, and explicitly restarts WildRig after
success or failure. Genuine custom pool acceptance remains unproven until an
actual custom share is accepted.
