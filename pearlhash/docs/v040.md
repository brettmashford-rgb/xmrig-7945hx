# v0.0.40: cache A once per nonce, keep B virtual

The v39 rig passed eighteen GPU commitment cases, matched a full production
CPU/GPU root and opening, and verified a fresh GPU-base V3 proof with the official
offline CPU verifier. Its commitment comparison measured 29.118443 s CPU versus
0.074480 s GPU opening construction (component timing, not miner throughput).
The five-minute live run searched 74,084,352 tiles and completed eight nonces.
It spent 0.440 s in base preparation, 5.129 s in nonce preparation, 3.108 s in cache
setup and 290.129 s in search. No custom share was attempted or sent. Only one
live job was processed, so its job mix differed from the earlier v38 run.

This release experiments with the now-dominant scan kernel. The existing virtual
path repeatedly synthesizes A signed-byte fragments from the same per-nonce
uniform/permutation data for many B tiles. CachedA uses the already-tested
materialize_selected_rows kernel to produce all A rows once in row-major order.
For m5121/K32768 the payload is 167,804,928 bytes (160.03125 MiB), capped at 256 MiB.
It never materializes the 8 GiB B matrix. Allocation initializes only the guard
bytes; no full A matrix is uploaded from CPU memory.

The new cached_a_virtual_b_scan keeps the twenty-argument ABI, one query per warp,
MMA sequence, prefix folding, digest, target comparison, generation tags and queue
format. A loads its cached 32-bit words, including the nonce tail in the last row.
B retains virtual signed-byte generation with a smaller sixteen-row uniform shared
cache per warp, padded to an eighteen-byte stride. Global descriptors and tile order remain unchanged; no index
remapping or alternate nonce coverage is introduced.

Attachment creates a separate ctypes pointer value and argument array; it never
mutates the original uniform A pointer or its allocation owner. A source wrapper
checks both materialization and original noise guards before returning results.
The backend retains the A cache across windows/retries, frees only its own A
allocations, and discards it on nonce completion, error or job replacement.
Independent CPU verification of complete hits and the existing proof/submission
gates remain active. The original virtual path remains the default unless the
explicit --cache-a option is passed.

Mandatory rig preflight checks eighteen CPU transcript/target/queue scenarios
across small boundaries, production first/last indices and reversed/tail maps.
It compares all 4096 transcripts for first/middle/end production windows. A timing
comparison uses sixteen exact production row-major windows, alternating baseline
and cached order, with preparation outside both scan timings. It includes A
materialization setup in the cached total. The cached path is preferred only if
this total beats baseline by more than three percent. Per-window timings are
saved locally. These are component measurements, not live mining throughput.

A fresh synthetic job must also produce an independent V3 proof accepted by the
existing official CPU verifier through the cached-A path. The already-validated
v39 GPU B commitment module is reused. No earlier full CPU commitment benchmark
or captured inputs are repeated. Only after correctness/proof checks pass AND the
cached path wins the component comparison does the installer start one bounded
five-minute live run with --cache-a. If it loses, the installer skips live mining
and restores WildRig so the experimental path cannot replace a faster baseline.

Host tests compile the actual A load helper, check row layout/padding, all-row
materializer arguments, original pointer immutability, caps, guards, foreign
attachments, retained buffers, stale-job cleanup and the comparison selection
rule. Existing nonce/cursor/proof/submit tests remain active. The scan PTX is
reproducibly built with NVRTC 12.9.86 from readable independent sources and the
verified v33 CUDA dependencies. No new native CPU binary or CUDA toolkit is
installed on the rig. GPU validation and timing are pending the rig run.

The shell temporarily stops/restores WildRig with a fifteen-minute fallback.
XMRig, clocks, service definitions and autostart remain unchanged. Pool share
acceptance is still unproven; status-report ACKs do not count as shares.
