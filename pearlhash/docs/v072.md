# v072: eight-step B sharing plus partitioned transcript folding

Combines the independently rig-tested winners: v070 cta_b8_scan (10.98% faster search than its v068 control) and v071 partition_pointer_scan (7.19% faster than its own v068 control). These were separate measurements with different windows; their gains are not added or multiplied. The actual combined performance remains pending the rig test. v066 remains the last validated live worker; this release performs an offline comparison only.

## Kernel

The combination uses v070's unchanged block traversal, eight-step producer/consumer buffer, complete row/column input validation, block-wide rejection, barrier placement, five advancing A pointers and six MMA instructions per K step. Inside each live consumer warp, v071's partitioned fold replaces four five-shuffle reductions with eleven shuffles and holds the transcript as two words per lane. Its tile/slot mapping is used during the unchanged concurrent hash/target/queue emission. Inactive consumer warps still produce B and reach every CTA barrier. Partially active quartets still run the complete warp fold; existing per-query masks restrict emission.

The original v070 eight-step control is included from its unmodified source. The actual v071 partition kernel body is copied unchanged into the new module, avoiding duplicate inherited kernel definitions. Host contracts compare that body directly with the validated v071 source. No new shared/global allocation, stream, queue ABI, permanent service or pool configuration is introduced.

The PTX retains 24 arguments and six MMA instructions per entry. The combined static K-loop has 19 shuffles versus the v070 control's 28. Its uniform and fragment shared arrays remain 3,072 + 4,096 = 7,168 bytes. Both CTA entries retain three static block barriers plus uniform input validation; the standalone v071 control has no block barrier. Registers, local memory and actual speed are reported on the rig.

It requires v070's preferred cta8-v070 comparison and v071's preferred partition-v071 comparison, each above the established 3% elapsed-reduction threshold versus its own v068 control. Their private reports remain on the rig; none is uploaded by this installer.

For two fresh production nonces, the preflight compares four 4,096-query windows against both winning controls. The standalone partition control is reordered by canonical tile ID; the CTA control uses the exact candidate traversal. Their eight control windows must agree before the combined outputs are checked. The candidate also checks sixteen independent CPU transcript samples, eighteen target/queue cases, a populated 67-query overflow, five malformed row/column map cases with partial blocks, all 28 allocation-guard faults, retained odd windows and stale cleanup. Shared geometry is required to survive all six production leases. Two newly generated V3 proofs must pass the installed official CPU verifier before timing.

## Fair comparison

Twelve rounds use all six permutations twice for cta8-v070, partition-v071 and combined-v072. Each round searches 524,288 tiles, a full 32-row-axis group, so different traversal orders cover the identical canonical set. Warmup, twelve timed windows and the separate diagnostic fit inside one nonce. Unique timed work is 6,291,456 tiles per mode. All modes retain independent A/B/geometry owners in one context. Setup/JIT and nonce/commitment preparation are excluded from primary timing and setup is separately reported.

The search driver contract remains 128 resets, 256 kernel launches, 128 stream waits and 128 readbacks totaling 64,512 bytes per mode, with zero search-time HtoD/context-wide waits. Timing reports speed ratios against both standalone controls. The combination is preferred only when it exceeds the faster control by more than 3% median elapsed reduction; otherwise that faster control remains preferred. This is search throughput, not a whole-miner or pool-acceptance result.
