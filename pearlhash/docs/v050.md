# v0.0.50: remove repeated host work from packed-direct windows

v049 completed its five-minute rig run with 137637888 tiles, 19 nonces started,
14 full nonces and 33603 packed-direct windows. Worker joined, exit code zero,
WildRig restarted. No share found/submitted; 20 report acknowledgements are not
accepted shares. Packed direct remains the preferred live development path.

Two new offline variants isolate hot-loop overhead; the v049 live worker is
unchanged. All existing scanner/collector entries and v048 readable PTX are
reused in place. No new GPU math, ABI, kernel, toolkit or native artifact.

1. Stream-reset: clear the two status u32 words with cuMemsetD32Async on the
   same nonblocking stream as scanner and collector. This removes the eight-byte
   host upload and per-window cuCtxSynchronize. Stream order establishes reset
   visibility. Stream synchronization/readback still occur before cursor credit.
   Mark the reset pending before enqueue; stale work after reset and before scan
   drains that stream before releasing any nonce allocations.
2. Lean: stream-reset plus one frozen scalar target binding per window. The
   target is uniformly uploaded once per nonce, so constructing/comparing 4096
   copies and repeatedly scanning them in validate_wide/populated_count/
   decode_wide is unnecessary. Scalar checks validate count, target, capacity,
   generation, owner, immutable batch and target binding. Candidate decoding
   retains length/count/overflow, index, duplicate, generation and target checks.
   Complete returned candidates still undergo independent CPU math verification.
   No CPU recomputation of misses. Planning/decoding misses is O(1) in tile count.

Every one of the original 28 guard endpoints and the snapshot window identity
are checked on every completed window. Queue overflow/retry and stale/cursor
handling are unchanged. Existing unused descriptor allocation is retained for
this isolated experiment; no allocation/guard-layout change is mixed into it.

Rig preflight compares each new variant with actual packed-direct-v048 dispatch
(the path integrated into v049) over first/row-crossing/middle/end 4096-query
transcript windows. Totals: eight full windows, sixteen independent CPU samples,
36 target/queue cases, two populated 67-query overflows, 56 deliberate guard
corruptions with fresh dispatches, two fresh V3 proofs through the official CPU
verifier, retained odd miss windows and stale rejection. Full success gates timing.

One synthetic production nonce/target and identical ranges compare current
packed-direct-v049, stream-reset-v050 and lean-v050. All use advance(4096).
24 rounds cover each of six orders four times, 65536 tiles/mode/round. Setup
is reported separately; primary timings have no driver instrumentation. A
separate diagnostic requires all three modes to retain 32 kernel launches,
16 stream waits and 16 readbacks (8064 bytes). Baseline requires 16 host uploads
(128 bytes) and 16 context-wide waits; both variants require zero of each and
16 cuMemsetD32Async calls. Prefer a new path only for greater than 3% elapsed
reduction. Output: LEAN COMPARISON, DRIVER COUNTS, lean-comparison.json.

62 host tests pass: scalar decoding versus the existing decoder on complete and
partial queues, malformed/stale/duplicate/target-failing records, scalar type
and range rejection, frozen owner/target binding, reset stream/order/dirty-status
clear, every guard on both variants, CPU digest mismatch rejection, stale reset
and scan cleanup with no cursor credit, exact diagnostic/range/order selection
and installer gating. Actual GPU correctness/proofs/performance remain pending.

Installer verifies 18 dependency manifests/files, the completed v049 result
(complete/no error/joined/packed-direct-one-stream-v049), and CPU library pin
from verified v031 metadata. It uses the already installed v048 PTX and v039
commitment PTX. No pool connection, login capture, continuous miner, clocks,
CPU XMRig, permanent service definition or autostart changes. No fee or copied
third-party miner code. No private wallet/capture/header/nonce/seed/proof is
published. The Termius wrapper schedules a 15-minute fallback before pausing
WildRig, bounds execution to 13 minutes and explicitly restarts it afterward.
Genuine independent-miner pool acceptance remains unproven.
