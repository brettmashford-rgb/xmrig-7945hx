# v074: four independent offline optimization experiments

This suite compares each target against the actual v070 CTA8 scanner. The v072 combination remains available separately; its measured 2.42% throughput gain did not meet the existing promotion threshold. No v074 GPU speedup is claimed before the rig results.

| Group | Candidates | Purpose |
| --- | --- | --- |
| blocks | small4, small8 | 128 threads, four consumer warps, four or eight K steps per shared B stage |
| pipeline | pipeline | Two dedicated producer warps overlap next B stage with eight consumer warps using alternating buffers; 320 threads |
| panel | panel | Build fragment-ready B for up to sixteen column tiles, then reuse across the complete row domain |
| batching | wide16k | Process 16,384 queries per dispatch instead of 4,096, with larger guarded buffers and complete overflow retries |

Seven independent preflights cover control, small4, small8, pipeline, panel-control, panel and wide16k. Each checks two fresh production nonces, eight transcript windows, sixteen independent CPU samples, two official V3 CPU proof verifications, targets, overflow, input-map failures, allocation guards and stale work rejection. The wide mode additionally checks a full 16,384-result overflow. A failed mode blocks its own timing group while other groups continue.

All traversals have a checked bijection to the same 8,388,608 canonical production tiles. Preparation identity is bound to the current mutable panel arguments. Results are credited only after complete queue decoding and CPU verification. Stale or overflowing partial work receives no cursor credit.

Blocks, pipeline and batching use twelve balanced rounds of 524,288 unique tiles per mode, with setup excluded and reported separately. Panel uses six balanced rounds of the entire 8,388,608-tile nonce, each starting cold. All 1,024 panel builds, their validity readbacks and their device work are inside every panel timing. A same-traversal panel-control isolates caching from ordering effects; the ordinary v070 control also remains in that group. Each round processes the same canonical work set in all modes. More than 3% median elapsed reduction against control is required for promotion.

Driver diagnostics are separate from primary timings. They assert expected launch, reset, synchronization and copy counts, including panel builds. Larger dispatches must reduce dispatch counts by four. Resource output reports registers, shared memory, local memory and CUDA's maximum active blocks/resident warps per SM for each launch size. These are residency limits, not measured achieved occupancy or utilization.

Build: NVRTC 12.9.86, compute_120, C++17. PTX is compiled twice and compared byte-for-byte. The unchanged v070 source is included directly; hash metadata records every transitive local include. Host tests cannot establish device correctness, concurrency behavior or speed; the launcher runs the GPU/proof gates before each benchmark.

Run tools/run_v074.sh on the existing Debian rig with its previously validated v070/v071 packages. The launcher downloads checksum-pinned files, schedules a thirty-minute WildRig recovery timer, stops pearl.service, and runs the suite with a 1,500-second deadline. Its exit trap restarts WildRig. CPU mining, clock settings and autostart configuration are unchanged. No pool connection or share submission is attempted.

Results: /home/user/pearlhash-dev-v0.0.74/*-comparison.json and suite-result.json. Combined console results and resources appear at the end of /home/user/pearlhash-v074-launch.log.

## Fixes for the v073 rig failures

The command-line parser now accepts control, matching the installer's seven-mode list. Previously argparse rejected control before creating its output directory. The shared GPU guard collector now permits 1 through 16,384 queries instead of stopping at 4,096. Its seven-argument ABI, snapshot format, guard validation and window identity checks are unchanged. The original collector is retained under a legacy symbol; every scanner in the suite uses the extended collector through the established symbol.

Regression tests call the actual parser for all seven modes, compile and execute the collector's shared validity predicate with boundary cases, and inspect the emitted PTX ABI and extended limit. This repair changes no hashing arithmetic or target semantics. GPU preflights must pass again before timing. No v073 files or logs on the rig are removed or overwritten.
