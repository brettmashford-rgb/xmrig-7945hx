# v0.0.31 reusable materialized-input experiment

The current production kernel reconstructs the constant signal plus deterministic
noise every time it loads an MMA fragment. This experiment generates selected
rows once on the GPU, stores exact signed bytes, and reuses them across queries.
The same MMA register layout, cumulative rank-boundary XOR, transcript rotation,
keyed digest, inclusive target comparison, generation tags and queue rules remain.

`materialize_selected_rows` uses the established virtual fragment loader, including
the final A row's nonce-tail bytes. `cached_tile_scan` loads aligned four-byte
fragments directly. There are no new block barriers. Host mapping deduplicates
selected global rows, preserves ordered/repeated query indices, rejects absent
rows, and caps the immutable materialized allocation at 128 MiB. A full 8-GiB B
matrix is never allocated. Guards protect the materialized rows and scan outputs.

The offline checker first runs eighteen new kernel scenarios over three existing
synthetic profiles: boundary/tail, actual production global first/last rows, and
reversed maps with signed tail extremes. Six target/queue scenarios cover max,
zero, inclusive equality, zero-capacity overflow, mixed overflow and complete
mixed results. Every query's transcript and candidate set is compared to the
independent scalar CPU reference, including high generation bits.

A second cross-product uses eight A tile groups and 32 B tile groups. Its full
256-query transcript set must match the old production kernel, and six spread-out
queries additionally match independent CPU math. Eight repeated rounds compare
both paths on identical inputs, with materialization time reported separately and
also included once in the cached total. Those are repeated component timings;
they are not unique mining throughput or pool acceptance evidence.

Three host tests cover deduplication/order, strict global index binding, absent
rows and allocation limits. NVRTC 12.9.86 actually produced readable sm_120 PTX;
a separate rebuild is byte-identical. No compiler is installed on the rig.
**Real GPU correctness and speed results are pending.** The new cache has not
been connected to live mining; its scheduler integration follows only if the rig
checks pass and timings justify it. No pool connection or shares in this test.
