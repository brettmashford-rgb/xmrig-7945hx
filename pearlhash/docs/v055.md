# v0.0.55: two quad5 loop scheduling experiments

The completed v054 live run searched 220626944 tiles, started 29 nonces and
finished 25 full nonces. Search took 267.774 seconds, nonce preparation
17.312 and cache preparation 10.689. All 53864 quad5 windows completed without
a reported error, the worker joined, and WildRig restarted with exit code 0.
No candidate or share was submitted; pool acceptance remains unproven.

This release is offline only. Both new kernels retain quad5 stride five,
eight warps per CTA, the same 24-argument ABI, cached A, packed four-row B,
MMA accumulator ordering, 128-K transcript boundaries, hash/target/queue tail,
status snapshot and all guards. The source includes the unchanged v052
kernels, so each comparison uses the actual quad5 control in the same module.
No new backend is selected by the live worker.

Test 1, grouped: b_quad_grouped_scan groups four 32-K iterations into one
128-K outer step, unrolls the four inner steps and folds the transcript at
the original boundary. There are 256 outer steps instead of 1024. This
changes scheduling and loop control, not the mathematical work.

Test 2, grouped plus early preparation: b_quad_early_scan retains those same
groups and prepares the next A/B operand set before the current two MMA
operations. Lookahead ends at the fourth step: no operand is read beyond
the current group or K domain. The compiler decides final instruction
scheduling; the driver JIT register/shared/local resource report and measured
hardware timing determine whether the attempt helps. No gain is assumed.

Before either timing test, both variants must pass four full 4096-query
transcript windows against quad5 (first, row crossing, middle, end), eight
independent CPU transcript samples, eighteen CPU target/queue cases, a
populated 67-query overflow case, all 28 guard faults, odd retained miss
windows, stale rejection and a fresh V3 proof through the installed official
CPU verifier. Totals: eight windows, sixteen CPU samples, 36 target cases,
56 guard faults and two fresh proofs. Incomplete/failed gates block timing.

Then compare_b_loop_loops.py runs twice: --variant grouped, followed by
--variant early. Each test prepares a synthetic production nonce shared by
its control and candidate. Two caches remain resident throughout its timing;
test 2 prepares its own synthetic nonce. Each test warms both paths, then
runs 24 alternating-order rounds of 65536 unique tiles per mode per round
with advance(4096). Both paths must cover identical intervals within each
round. The primary timing has no driver wrapper. Separate diagnostic work
requires 16 status resets, 32 launches, 16 stream waits, sixteen 504-byte
readbacks (8064 bytes), no host uploads and no context synchronizations.

Each test reports median throughput, setup time, relative gain, preferred
mode and kernel resources. A candidate must reduce median elapsed time by
more than 3% to be preferred. Reports: grouped-comparison.json,
early-comparison.json and two-test-summary.json. No automatic live adoption.
Progress is printed at each transcript window and timing round.

The installer verifies 23 dependency manifests/files through v054 (CPU library
pin read from installed verified v031), requires completed/joined v054 quad5
live results and prior v052 proof/performance results, then downloads the
pinned readable own-source PTX. No CUDA toolkit or pip package is installed
on the rig. A failing first comparison prevents the second, and neither
failed comparison produces a completed two-test summary.

92 targeted host tests pass. They cover exact offset/read ranges, transcript folding with wrapping
accumulators, verbatim final hash/queue code, both PTX entries and ABI,
backend selection, driver/reset/readback behavior, stale cancellation and
cleanup, paired sample/order/interval controls and installer fail-closed
proof/live/comparison gates. Actual GPU correctness and performance for the
new kernels remain pending rig execution.

No pool connection or share submission occurs in this release. No private
wallet, capture, header, nonce, seed or proof is published. All miner sources
are our own. CPU XMRig, clocks, pools, permanent services and autostart are
preserved. The Termius launcher schedules a 15-minute WildRig fallback before
stopping pearl.service and explicitly restarts it on exit. No continuous
custom miner is installed.
