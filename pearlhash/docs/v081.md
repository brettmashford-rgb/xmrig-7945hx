# V081: fixed-work rectangular compute layouts

First experiment for architecture-targets.md target 1. V080 kept the actual V079 four-step pair-direct kernel. Its eight-step candidate was only 1.77% faster, below the >3% elapsed reduction required for promotion. V080 live completed 673,054,720 tiles over approximately 300.138 seconds, no submitted shares, all resources joined and WildRig restored.

This offline test compares unchanged pair-direct against two aspect ratios. Every block still has eight warps, 256 threads, four tiles per warp, 32 canonical tiles total, four K32 steps per B stage and exactly the same six-MMA arithmetic and K128 checkpoints. It is not the earlier 512-thread block experiment, nor the losing eight-tile-per-warp packing. Larger column groups trade more B reconstruction/shared storage against a smaller A working set and potential A-cache reuse; neither outcome is assumed.

Candidates use direct A loads and no A staging. Consumer warp side=warp%Columns and quartet=warp/Columns. B producer column=warp%Columns, starting K32 step=warp/Columns, stride=8/Columns. Thus every column/step/fragment/lane is produced once and read by its correct consumers. Every thread participates in block barriers, including inactive row or final partial column groups. Invalid axis data causes collective rejection. Direct A pointer advancement, accumulators, transcript folding, keyed digest, target comparison, audit and candidate emission remain unchanged from V080. The control and guard collector PTX entries are byte-identical to V080.

Host C++/UBSan checks enumerate all 8,388,608 production tiles for each layout and prove bijections, inverse mappings and identical 524,288-tile canonical row bands. They check block/warp-to-canonical coordinates for full and partial groups, all K positions' B producer/consumer fragments and no aliasing. Python checks complementary partial-column profiles; mock driver tests check retained owners, stale cancellation, full 16K overflow retry and independent candidate verification dispatch. PTX checks verify the 24-argument ABI, six MMA instructions and shared sizes. These checks do not execute the GPU.

Fresh rig gates for each mode use the independent V070 control by canonical tile ID: two production nonces, eight 16K transcript windows, sixteen independent CPU samples, targets/partial and 16K zero-capacity queues, 28 buffer guards, five invalid-axis cases, retained/stale owners and two fresh V3 proofs checked by the official CPU verifier. An additional 160x234 profile has 16 row axes and nine column axes: it exercises full column blocks followed by a final partial block, row-band and column boundaries and CPU samples. All three modes must pass before timing.

Timing: twelve balanced rounds covering all six mode orders twice, 524,288 tiles/round, 6,291,456 unique tiles/mode. Each interval is the same canonical row band despite different visit order. Setup/JIT and telemetry excluded; setup reported. Separate driver diagnostic requires exactly 32 resets, 64 launches, 32 waits and 32 x 504-byte readbacks per mode with no search uploads or context-wide synchronization. Candidate preference requires >3% lower median elapsed than the actual paired control.

Power: automatic read-only NVML sampling at 200 ms, two balanced rounds, one conditioning full nonce then three measured full nonces/trial; 50,331,648 measured tiles/mode.
