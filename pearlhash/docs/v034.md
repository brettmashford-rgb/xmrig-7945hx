# v0.0.34: offline dispatch profiler

The v33 RTX 5060 run passed all eighteen target/queue cases and the complete
4096-query transcript comparison. Across eight repeated synthetic rounds,
virtual scanning took 0.398102 s, fragment scanning 0.717101 s, and cooperative
scanning 0.767628 s. Materializing the cache cost another 0.120397 s. These
experiments do not justify replacing the existing production virtual kernel.

This release changes no GPU math or live mining path. It profiles the existing
three paths using the verified v33 PTX and the same synthetic 32 by 128 query
grid. A complete transcript comparison precedes measurements. Prior independent
CPU checks are not repeated. Eight rotating rounds pair instrumented and plain
calls, alternating pair order to reveal instrumentation disturbance.

Host wall-time categories are allocation, free, upload, download, synchronization
wait, kernel launch API, other driver calls, event instrumentation, and remaining
Python/bookkeeping time. Buffer creation, query mapping and serialization remain
in the last category; it is not all descriptor serialization. Transfers include
the existing guard checks. All existing guard and returned-candidate checks stay
active. This experiment uses zero targets and no proof construction.

CUDA events bracket cuLaunchKernel in the same default stream. The elapsed event
interval is reported separately: it overlaps synchronization waits and must not
be added to host categories. It may include scheduling and submission gaps; it
is not an instruction-cycle or exclusive GPU utilization measurement. Existing
synchronization remains unchanged. Events are queried only after completion.

Reference: NVIDIA CUDA Driver API, Event Management:
https://docs.nvidia.com/cuda/cuda-driver-api/group__CUDA__EVENT.html

The installer verifies installed v33/v31/v27/v17 source manifests and the local
CPU library through the already-installed v31 manifest. It requires a successful
v33 result and installs only this profiler into a new directory. No pool IO,
share submissions, native binary downloads, GPU recompilation, clock changes or
service changes occur within Python. The accompanying shell temporarily stops
WildRig with a fallback restart timer and restores it after the run.

GPU timings remain pending until this profiler runs on the rig. No mining-rate
or pool-acceptance claim is made.
