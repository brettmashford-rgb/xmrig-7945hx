# v0.0.56: early A/B preparation without grouping

The completed v055 GPU tests found grouped iterations 7.09% slower than the
quad5 control, while grouped plus early A/B preparation was effectively tied
with its control (-0.07%). The grouped kernel used 40 registers per thread;
grouped plus early used 56. Neither spilled to local memory, and both passed
the GPU correctness/proof gates. Those tests used separate synthetic nonces,
so recovering the grouping loss does not establish an early-only speedup.
The live development path remains v054 quad5.

This release tests early operand preparation alone. early_only_scan.cu
includes our existing b_loop_scan.cu for its LoopOperands loader and unchanged
quad5 control entry. The new b_quad_early_only_scan entry keeps the original
32-K loop (1024 iterations), explicitly disables unrolling and keeps the
original transcript fold verbatim at every 128 K. It prepares the first
operand set before the loop, prepares the next set before the current two
MMA operations, and carries that set into the next iteration. A uniform
range guard prevents preparing offset 32768; the last valid set starts at
32736. No four-step grouping or grouped transcript handling is used.

The new entry retains stride-five shared storage, eight warps per CTA, the
24-slot ABI, cached A, four-row packed B, MMA order, final transcript/hash/
target/queue code, packed status/guards and independent CPU candidate checks.
The compiler/JIT determines final scheduling and resources. No speedup is
assumed; hardware register/shared/local resource facts are reported.

Before timing, check_early_only_job.py requires four full 4096-query transcript
windows against actual quad5 (first, row crossing, middle, end), eight
independent CPU transcript samples, eighteen target/queue cases, a populated
67-query overflow case, all 28 deliberate guard corruptions, a fresh early-only
candidate and V3 proof verified by the installed official CPU verifier,
retained odd miss windows, stale rejection and allocation cleanup. A failed
or incomplete correctness/proof gate prevents benchmarking.

The paired offline benchmark uses the same synthetic production nonce, target
and tile intervals for control and candidate. Both caches remain resident.
It warms both paths and runs 24 alternating-order rounds of 65536 unique
tiles per mode, advance(4096), with an uninstrumented primary timer. A separate
65536-tile diagnostic must retain sixteen stream-ordered resets, 32 launches,
16 stream waits and sixteen 504-byte downloads (8064 bytes), zero host uploads
and zero context synchronizations. A candidate must reduce median elapsed time
by more than 3% to be preferred. No automatic live integration occurs.

Report: early-only-comparison.json. Terminal output: EARLY ONLY COMPARISON,
DRIVER COUNTS, KERNEL RESOURCES. The installer verifies 24 installed source/PTX
manifests through v055, checks completed/joined v054 live results, completed
v055 tests and v052 proof/performance gates. CPU library hash is read from
installed verified v031 metadata. It downloads pinned readable own-source PTX;
no toolkit or pip dependency is installed on the rig.

86 targeted host tests pass: safe lookahead offset range and original loop,
verbatim transcript fold and final queue/hash tail, new PTX ABI/barriers/MMA
body, actual quad5 control selection, retained/reset/readback behavior, stale
cancellation and cleanup, balanced timing and same intervals, installer
proof/guard/stale/report gates and existing backend/queue/cursor tests.
The repeated NVRTC build is byte-identical. GPU correctness/performance for
the new entry remain pending rig execution.

No pool connection, submission or live worker change occurs. Genuine custom
pool acceptance remains unproven. No private wallet, capture, header, nonce,
seed or proof is published. All miner source is our own and fee-free. CPU
XMRig, clocks, pools, permanent services and autostart are preserved. The
launch wrapper schedules a 15-minute WildRig fallback before stopping
pearl.service and explicitly restarts it on exit. No continuous miner is
installed.
