# v076: CTA8 consumer scheduling on the winning 16K baseline

V075 rig results retained wide16k: 2,094,986 median tiles/s, 93.8 W average GPU-board power and 22,173 tiles/J. Small4+16K lost 18.4% speed. Four-step scheduling recovered most of that loss but remained 2.6% slower and 8.1% less efficient than wide16k. Those results do not establish that scheduling also helps CTA8.

V076 compares the actual unchanged wide16k control with two 256-thread candidates. Both retain eight cooperative K32 production steps, 32 canonical tiles per block, the same 16,384-tile host dispatches, B sharing, A pointers and six MMA instructions per step. The only change to the copied CTA8 device body is parameterising the consumer-loop unroll directive: four steps or eight steps. Accumulator order, every K128 cumulative checkpoint, fold, transcript, target, queue, barriers, map validation and final A bounds are preserved exactly. Source-equality tests enforce that restriction. More unrolling may increase registers, spills or instruction footprint; no gain is assumed.

| Mode | Kernel entry | Threads | Consumer unroll |
| --- | --- | ---: | ---: |
| wide16k | cta_b8_scan | 256 | 1 (unchanged control) |
| wide16k-schedule4 | wide_schedule4_scan | 256 | 4 |
| wide16k-schedule8 | wide_schedule8_scan | 256 | 8 |

All three modes independently run the established fresh correctness/proof gates before any timing: two production nonces, eight 16K transcript windows by canonical ID against v070, sixteen CPU transcript samples, target and populated/zero/full-16K overflow checks, 28 guard endpoints, five invalid map checks, retained/stale ownership and two official CPU-verified V3 proofs per mode. Failure blocks timing.

Speed timing uses twelve balanced rounds covering all six orders, with 524,288 identical canonical tiles per mode per round and 6,291,456 distinct timed tiles per mode. Initial setup and telemetry are excluded. An instrumented diagnostic separately requires the same driver calls and readback bytes. The unchanged 16K control is the promotion reference; a candidate must reduce median elapsed time by more than 3%. The eight-step/four-step ratio is diagnostic only.

The same command automatically measures approximate GPU-board energy after speed timing: read-only NVML samples every 200 ms, two balanced rounds per mode, one conditioning nonce and three measured complete nonces per trial. Each mode measures 50,331,648 tiles. Fresh nonce preparation, A setup, search and cleanup are included; initial job/base/B/geometry preparation is excluded. Samples, gaps and invalid sensor handling use the unchanged v075 telemetry implementation. Board power is not wall-plug power. Kernel-active and memory-active percentages do not establish Tensor Core saturation, achieved occupancy or bandwidth saturation. Offline tiles/J cannot be compared directly to another miner's H/s/W.
