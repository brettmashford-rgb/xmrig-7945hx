# v0.0.44: populated-only candidate queue readback

The v043 rig comparison measured 356047 versus 338944 tiles/s in the one-stream
and two-stream full search loops respectively. The separate 65536-tile diagnostic
read 5952 device-to-host bytes for one stream and 2888832 for two streams. This
confirmed excess traffic, but did not isolate its effect on execution time.

This release changes only stream queue readback. After stream completion, read
and guard-check the 8-byte status first. Validate total against query count and
overflow against ORIGINAL queue capacity before using either as a read length.
Download exactly min(total,capacity)*44 bytes. Empty queues still check both
queue guards but read no payload. Candidate decoder receives the populated
capacity: on a complete queue this equals total (overflow remains false); on an
overflowing queue it equals original capacity (overflow remains true). Existing
record count, ID uniqueness, generation tag, target and CPU math checks remain.
No host padding allocation or kernel/ABI/target/generation rule changes.

Mandatory rig gate runs eighteen profile/target/queue scenarios in both streams:
three profiles, all hits, misses with nonzero capacity, equality, zero capacity,
mixed overflow and mixed complete results. CPU transcripts/digests, returned
sets, guards, partial queue credit and exact payload read sizes are checked.
No old proof or kernel benchmark suite is repeated.

Then rerun the v043 twenty-round full-loop comparison with unchanged one-stream
baseline and compact two-stream worker. Same fresh synthetic production nonce,
target, ranges, actual advance cadence, resident caches, alternating order and
separate uninstrumented timings/driver-count round. New report labels the compact
readback explicitly. No pool connection or live worker selection is made; this
is a component test, not mining hashrate, pool acceptance or bandwidth saturation.

Installer verifies pinned v043 completion and all installed source/PTX/library
manifests. New source is installed separately and imported first; old version
folders are not modified. Termius wrapper restores WildRig after comparison and
schedules a 15-minute fallback restart. XMRig/clocks/service definitions unchanged.
