# v0.0.38: validate pattern axes once and assemble canonical descriptors

The v37 live profile located the remaining host bottleneck. Over 65,536 plain
production tiles, planning took 0.768595 s, preparation 0.586424 s, and scanning
plus checks 0.309750 s (1.687864 s total). The instrumented CPU profile identified
WideBatch construction/index validation and QueryPacker.axis as major costs.
Instrumentation disturbed CPU timings, so the plain measurements are the baseline.

FastPlan snapshots the complete canonical PatternDomain axes once per nonce.
Production caps are 512 A groups and 16,384 B groups. Each immutable axis stores
its exact global indices and the established padded 32-u32 descriptor bytes.
Construction checks bounds/types, exact canonical pattern order, counts, and
serialized bytes. Dataclass replacement/direct construction cannot introduce
noncanonical axes or inconsistent descriptors without validation failure.

FastBatch validates an interval of up to 4096 tiles in its own plan. Its maps and
queries are immutable lazy sequences: range scheduling obtains their length, while
only actual returned hits need TileQuery objects. Descriptor assembly joins cached
row prefixes and B descriptors; it handles row crossings and final partial batches
without changing global row-major IDs. It neither emits duplicate queries nor
skips valid intervals. No per-tile GlobalBatch index validation or QueryPacker.axis
walk is required after plan construction. Bounds, queue results, guards and
64-bit generations retain their existing dispatch checks.

FastCandidateBackend connects the new plan to the existing reusable virtual GPU
kernel, noise cache, NonceSearch cursor, and proof/submission controls. Overflow
retry uses the same prepared batch. Cancellation during a launch cannot commit
its cursor or credit candidates. Complete hits still receive independent CPU
math checks using their original global indices. The live worker selects this
backend and identifies v038; pool targets, nonce/seed derivation, proof format and
connection behavior are unchanged. No captured share or synthetic proof is sent.

Host tests compare complete small-domain maps and descriptor bytes; production
start/middle/end/row-crossing batches; 1000 deterministic random IDs; complete
8,388,608-tile interval coverage; malformed or foreign plans; lazy query creation;
overflow retry; buffer ownership; and replacement during a launch. Existing cursor,
submission-gate and bounded worker tests remain applicable. A local development
CPU comparison of 32 production windows verified all descriptor bytes matched;
its timings are not rig or miner throughput measurements.

The rig preflight constructs a fresh synthetic V3 proof through the new planner
and requires the existing official offline verifier to accept it. It also checks
two resumable windows and stale search/proof rejection. A production-shaped
comparison then times old versus new planning/packing over the same 32 consecutive
4096-query windows, checks every descriptor/target byte, reports axis setup cost,
and compares all GPU transcripts for first/middle/end production windows. This
uses synthetic seeds and zero targets for comparison; it is a component test.

Only after those checks pass does the installer start one bounded five-minute
live connection with the actual received pool target and at most one fresh custom
share. It requires the completed v37 diagnostic and verifies prior installed
source/PTX manifests and the local CPU library through the existing v31 manifest.
The shell temporarily stops/restores WildRig with a 15-minute fallback timer;
XMRig, clocks, service definitions and autostart are not changed. No continuous
service is installed. Rig validation and live speed/acceptance results are pending.
