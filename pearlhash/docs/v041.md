# v0.0.41: offline one-stream / two-stream comparison

Reuses the rig-validated v040 cached-A kernel unchanged. One CUDA context,
one shared read-only A cache and noise tables; two private descriptor, target,
status, candidate queue and transcript buffer sets. Streams use NON_BLOCKING.
All descriptors/uploads/reset operations finish before launches. Paired kernels
are enqueued before either wait, and both wait before any synchronous readback.
This tests concurrent kernels; it does not test asynchronous transfer overlap.

Fifteen independent CPU transcript/target/overflow scenarios run in both streams,
including partial 67-query grids, equality, zero capacity and overflowing queues.
Full 4096-query windows at first/middle/end are compared against the validated
v040 synchronous dispatch, separately for both streams.

Two warmup pairs, then twenty alternating-order rounds. Each mode searches the
same two disjoint consecutive 4096-query production windows per round. Serial
control launches both kernels onto one stream and waits between them. Parallel
mode uses both streams. Both modes stage and read back identically. Report full
wall times and launch/wait times separately; primary median wall includes
uploads, resets, launch, wait, readback and guard checks, but excludes common
planning and shared nonce/cache setup. Samples are retained. Prefer two streams
only with a >3% wall improvement. Selection is advisory: no live miner changed.

This is an offline synthetic component experiment, not a pool rate, acceptance
verdict, bandwidth measurement, occupancy measurement or proof of simultaneous
hardware execution. Concurrent streams permit overlap; the scheduler may still
serialize kernels if resources are saturated. No network connection or shares.
Only benchmark-owned streams and buffers are freed, after synchronization.

Installer verifies pinned installed dependency manifests and v040 completion;
source and CPU library hashes must match. No old proof checks are repeated.
The Termius wrapper pauses pearl.service with a 15-minute fallback restart,
and restarts it on completion. XMRig and clocks remain as configured.

CUDA stream API reference:
https://docs.nvidia.com/cuda/cuda-driver-api/group__CUDA__STREAM.html
