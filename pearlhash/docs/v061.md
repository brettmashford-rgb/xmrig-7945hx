# v0.0.61: cache A's unchanged Merkle frontier across nonces

v060 shared-B is the validated offline scanner winner: 1070404.59 tiles/s
versus v059 881361.31 (+21.45%), with 56 registers/thread, 24576 shared bytes
and no local spill. The order-only control measured 993695.72 (+12.75%).
v061 keeps the v060 scanner/PTX unchanged and experiments with nonce preparation.
It performs no live integration or pool connection.

prepare_nonce currently rebuilds all 163872 A leaves and 163871 internal
nodes per production nonce, although only the final sixteen matrix bytes
change. NonceCommitmentCache builds the canonical constant A tree once per
job, independently verifies its last-row opening, then extracts and verifies
the fixed sibling frontier for the last leaf. For this production tree the
frontier has seven actual parent hashes; promotion through the other tree
levels requires no hash. The frontier is immutable, private data omitted from
repr, bound to job key/m/K, and constructible only through its verified builder.

For each new nonce, the existing nonce_tail calculation determines the same
sixteen bytes as before. The cache hashes that last chunk and folds its fixed
siblings with the original keyed parent and final-root flags. The existing
independent sparse Opening verifier checks every resulting root again. Thus
each production root update costs two leaf hashes and fourteen parent hashes
including verification, rather than a whole-tree reconstruction. No native
library replacement, new CUDA kernel or toolkit is needed.

prepare_cached_nonce retains the existing base identity/opening verification,
explicit eight-byte worker/miner inputs, current-job checks, seed derivation,
ConstantProfile and Nonce return contract. It rejects foreign cache keys or
dimensions and stale jobs before/after native work. It uses a last-leaf
membership proof internally, not a row-zero opening: no caller receives an
incomplete row opening. Actual candidate build_proof remains unchanged and
independently recomputes full fresh row openings and verifies commitment roots.
Existing prepare_nonce and live-worker defaults are untouched.

58 targeted host tests pass, including full-tree root equality for six power-
of-two/irregular matrix shapes through m5121, three tails per shape, complete
nonce context equality, no repeated full-tree call after cache construction,
immutability/corruption/key/dimension/type rejection, stale build and stale
root updates, cached timing amortization, installer gates and existing v060
canonical mapping/overflow/guard/lifecycle plus nonce/submission tests.

A development-host CPU run used an independently built CPU B base and all
20 actual production nonce pairs matched byte-for-byte. Median full-tree
preparation was 0.37255375 seconds versus cached 0.000312076 seconds. Cache
construction took 0.35848519 seconds. The 20-nonce totals including that build
were 7.53703189 versus 0.365852021 seconds (20.60x). These are development CPU
preparation measurements, NOT rig GPU throughput or whole-miner speedups.
Rig timing and the new cached-nonce proof path remain pending execution.

Before rig timing, four full production contexts must match old prepare_nonce
exactly, including root, seeds, tail, worker/miner and base identity. Stale
preparation is checked before and after root computation. The same cache is
then reused for two distinct fresh synthetic nonces, each compared with the
old context, scanned using unchanged v060 at a nonzero canonical tile, built
into a fresh V3 proof and passed to the installed official CPU verifier.
Retained odd miss windows, stale scan rejection and GPU cleanup are required.
Missing/failed equality, reuse or proof gates block timing.

The benchmark times 20 alternating-order pairs of identical production worker/
miner nonces. Shared B-base preparation is excluded. The cached A frontier is
built once and its time is explicitly added to the cached 20-nonce total.
Equality comparison occurs outside primary timing. It reports median nonce
seconds, steady preparation speedup, cache build cost, amortized total speedup
and a preference requiring more than 3% total elapsed reduction. It does not
measure GPU search tiles/s. Output NONCE COMPARISON; nonce-comparison.json.

The installer verifies 29 dependency packages and completed v060 benchmark,
canonical mapping and proof gates before using its unchanged installed readable
PTX. CPU library pin is read from verified installed v031 metadata. No toolkit,
pip dependency or binary archive is installed. No private wallet, capture,
header, nonce, seed or proof is published. Sources are our own and fee-free.
Pool acceptance remains unproven. CPU XMRig, clocks, pools, permanent services
and autostart stay intact. The checksum-pinned short launcher schedules a
15-minute WildRig fallback before stopping pearl.service, bounds execution/
cleanup to thirteen minutes and explicitly restarts WildRig on exit.
