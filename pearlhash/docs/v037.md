# v0.0.37: profile actual live production windows

The completed v36 run searched 7,806,976 tiles across three interrupted nonces.
It spent 87.075 seconds in B commitment preparation and 209.586 seconds in search,
with 1906 successful dispatches and only fifteen dispatch-buffer allocations.
No custom share was attempted or sent. This confirms buffer reuse but no overall
improvement relative to the previous bounded run. Synthetic grid component gains
must not be presented as live miner gains.

This diagnostic changes no GPU math or mining backend. It receives a supported
V3 job from the existing pool.pearlhash.xyz:9000 endpoint, uses that job's real
profile/target and a fresh nonce, and prepares the production commitments/seeds.
The receiver and latest-job worker retain the existing cancellation controls.

The sampler advances the normal NonceSearch by 4096 tiles over 32 consecutive
row-major windows. Alternating windows are plain or instrumented. Instrumented
windows use the already-tested CUDA event profiler plus cProfile around the
complete search.advance call. TimedPlan measures only generator advancement:
planning and validation of each WideBatch, excluding consumer/backend work.
PreparedCandidateBackend already tracks batch serialization and dispatch time.
Those separate totals, CUDA intervals, driver categories, and the twelve largest
cumulative CPU function entries are written into the private result report.

Plain/instrumented windows are adjacent and distinct, not identical-input paired
benchmarks. cProfile changes CPU execution costs; its counters locate expensive
functions and the plain windows supply a disturbance control. CUDA event intervals
overlap host synchronization waits and can include submission gaps; never add
them to host wall time. No inference of mining throughput or power is made.

At most 131,072 tiles are searched for one successfully completed job. A valid
candidate ends diagnostics without proof construction or submission. An arriving
replacement cancels and closes the old search, then the worker may try the latest
job within the same 90-second receiver limit. In-flight native CPU calls must
finish before cleanup. Partial samples are retained and labelled incomplete.

No SubmissionGate exists in this tool. It sends only pool login messages; it
never sends submit or report_info. The fresh offline proof test is not repeated.
The installer requires successful v36 preflight/live completion and verifies all
runtime sources/PTX plus the local CPU library through the pinned v31 manifest.
The v34 event profiler source is verified separately. Saved credentials stay local.
No native downloads, new GPU compilation or miner service installation occur.

The shell temporarily stops WildRig and restores it afterward, with a five-minute
fallback timer. It leaves clocks, service definitions, autostart and XMRig alone.
Host tests check exact batch/map preservation, timing exclusion across generator
yields, disabled instrumentation, empty profiles, login-only traffic, worker join
and cleanup. GPU measurements are pending the rig run.
