# V084: exact checkpoint-local B-basis projection

This is the first structured-noise algebra experiment. V083 retained pair-direct: native direct gained only 0.37% and CUDA Graphs 0.22%, with the scanner event interval covering approximately 94% of the instrumented baseline wall time. V084 changes the matrix representation while preserving every K128 checkpoint; it is not another dispatch adjustment.

## Exact identity

Within one K128 checkpoint, let `a[l] = actual_A[l] - 64` and let B's rank-128 uniform row be `U`. B's existing permutation supplies indices `p[l], s[l]`, so `B[l] = 64 + U[p[l]] - U[s[l]]`. Define:

```
X[r] = sum(a[l] where p[l] = r) - sum(a[l] where s[l] = r)
A_sum = sum(a[l])
B_sum = sum(U[p[l]] - U[s[l]])
delta_dot = X dot U + 64*A_sum + 64*B_sum + 524288
```

This is ordinary integer distributivity applied separately at every checkpoint. It also handles the nonce-tail row: `a` is derived from the actual materialized signed-byte A, not from an assumption that its signal stays 64. Uniform values are in [-32,31], normal noise in [-63,63], and actual materialized operands stay in [-127,127]; ordinary operands do not need an additional modulo-256 approximation.

Projected X can exceed signed-byte range. Store its signed low byte `L` and every nonzero correction `H = (X-L)/256`, so `X dot U = L dot U + 256*(H dot U)` exactly. No high term is dropped. The prototype reserves 128 correction records per physical A-row/checkpoint, so even an adversarial checkpoint cannot overflow its correction list. Records carry the coefficient index and signed high term. Accumulation uses the existing int32 representation.

The optional development probe sampled 2,097,152 coefficients from 64 physical rows of one synthetic production nonce: 0.3536% needed correction, averaging 0.453 records per row/checkpoint, maximum five in that sample. This is an illustrative observation, not a density guarantee. The code retains full worst-case capacity. Independent scalar tests verify all 256 checkpoints and the complete transcript for fresh seeds and tail rows, plus forced large corrections and the B coefficient +128 case.

## GPU experiment

| Mode | A representation | B in scan | Checkpoint correction |
| --- | --- | --- | --- |
| pair-direct | Existing materialized A | Existing repeated B reconstruction | Existing arithmetic |
| projected-sparse | Projected low bytes | Fixed rank-128 uniform fragments, staged once | Exact A/B residual sums and all signed high records |

Both modes retain the 16x2 layout, four canonical tiles per warp, 256 threads/block, paired traversal, six MMA instructions per K32 step and all 256 K128 folds. The existing pair-direct and guard-collector PTX entries are byte-identical to V080. The projected mode does not reduce the MMA count. It removes B reconstruction and block barriers from the hot K loop, trading that work for preparation, extra buffers and sparse scalar correction. It may lose on registers, spills, memory traffic or correction overhead; speed is not assumed.

New preparation kernels generate B residual sums per job and A projections per nonce. B coefficients use an exact correction for the possible +128 coefficient rather than treating it as -128. The scanner ABI adds four pointers to the existing 24 arguments: A residual sums, correction counts, correction records and B residual sums. Each checkpoint adds its exact bias/correction into the cumulative accumulators before the unchanged transcript fold and candidate emission.

## Memory and job binding

The production A projection reserves approximately 488 MiB, in addition to the existing approximately 160 MiB A cache. The per-job B residual table is 128 MiB. Buffers are bounded to m<=8192 and n<=262144, K32768/rank128/fill64. Unused correction slots are never read; preparation initializes all used low bytes, sums, counts and records. Both endpoints of every new allocation are guarded. The projected snapshot covers 38 guard endpoints and is 664 bytes; the unchanged control covers 28 endpoints and 504 bytes.

B residuals are tied to the same job/seed/permutation as the existing B owner and reused across nonces. A projections are rebuilt for each fresh nonce and include the tail. Existing ownership, generation checks, exact CPU candidate verification, queue overflow retry and cleanup remain in force. Additional tests inject failures in both job and nonce preparation and verify that shared owners are retained or released appropriately.

## Rig gates before timing

Both modes independently run the established production transcript, target, invalid-map, retained/stale ownership and official V3 proof gates against independent V070 and scalar references. The control faults all 28 guard endpoints; the candidate faults all 38. Full 16K zero-capacity overflow and partial populated queues are checked. Odd-column/partial windows remain included.

The candidate also runs standalone preparation edge kernels: a forced B basis coefficient +128, exact B sums, a tail-like A checkpoint with signed high corrections -12 and +12, independent expected low bytes, residual sum, correction counts/records and all allocation guards. These non-proof edge fixtures run in separate scratch buffers; the proof gates still use fresh legitimate nonce/job bindings.

## Fair speed, whole-nonce cost and energy

Twelve alternating balanced rounds compare the same 524,288 canonical tiles per mode per round, 6,291,456 unique timed tiles per mode. Ready-to-scan timings exclude preparation, which is reported separately. Driver diagnostics require 32 resets, 64 launches, 32 waits and complete per-window guard/status readbacks; the candidate's larger snapshot is charged in full.

Full-nonce trials then include fresh nonce preparation, original A materialization, the extra projection, full scan and cleanup. Two rounds condition one nonce and measure three more per mode, for 50,331,648 measured tiles per mode. Whole-nonce wall time is recorded even when NVML is unavailable. When supported, 200-ms read-only NVML sampling also reports approximate GPU-board energy, clocks and limiting flags. These are not wall-plug measurements or Tensor Core saturation measurements.

A candidate preference requires more than 3% lower elapsed in both ready scan and whole-nonce measurements. The upfront job/B projection cost is reported separately with its estimated break-even nonce count. That break-even is a measured amortization calculation, not a claim about actual pool job lifetimes. A steady-job preference is useful only after sufficient nonces amortize the extra job setup. There is no automatic permanent promotion.
