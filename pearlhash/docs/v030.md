# v0.0.30 target and work diagnostics

The bounded live runner now records per-generation tile counts, nonce counts,
base/nonce/cache/search/proof times, and booleans identifying header, target,
extranonce, metadata and token changes. Credentials, nonce values, headers and
job keys are not written to these diagnostics. The actual received target is
preserved for search; no easier target or captured share is substituted.

For inclusive 256-bit digest bound B, a uniform digest passes with probability
(B+1)/2^256. Diagnostics report its reciprocal as mean tiles per candidate,
expected candidates across each generation's completed work, and the chance of
at least one candidate under an independent uniform-digest model. These model
values are not pool verdicts or measured share intervals.

`--observe-target` receives one supported job and exits without preparation,
GPU creation, status reports or share submission. The short installer uses this
mode first, to establish the live target before spending another search window.
The ordinary bounded search remains available with the previous five-minute cap.
The receiver identifies itself truthfully as `pearlhash-independent/0.0.30`.

Validation includes inclusive-bound arithmetic, extremes, changed-field
classification, copy isolation and invalid counters, plus a scripted observation
that asserts no GPU/preparation calls and only a login write. The existing runner
proof/send/correlated-verdict and nonce rollover tests still pass with fake GPU
and pool replies. Prior real GPU kernel checks are reused unchanged.

No real custom share acceptance or production throughput improvement is claimed.
