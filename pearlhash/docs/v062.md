# v0.0.62: job-resident B tables and bounded live integration

B uniform noise (32 MiB) and permutation data (128 KiB) use a seed bound to the job key and B commitment. Generate both once per processed job, and lease their guarded allocations to successive nonce searches. A noise, tail, materialized A, maps and dispatch remain owned by each nonce. Reject foreign devices, job keys, profiles, closed owners and overlapping leases. Closing a nonce releases its lease; closing a leased owner is rejected. Every window retains all 28 guard endpoints, independent complete-candidate CPU checks and canonical tile IDs.

This package integrates the rig-validated v060 shared-B GPU scanner and v061 verified A-root frontier into the bounded worker. It reuses the installed readable v060 PTX byte for byte; there is no new GPU kernel or native archive. CPU library integrity still comes from the installed verified v031 manifest. Full proof construction and submission gates remain unchanged. Assigned extranonce as worker nonce and genuine pool acceptance remain unproven.

The installer verifies 30 installed dependency manifests, completed v060 GPU gates and completed v061 proof/equality/timing results. New offline preflight checks four production 4096-tile transcript windows across two distinct nonces against freshly generated B tables, eight independent CPU transcript samples, all 28 deliberate guard faults, four complete nonce contexts, stale/retained-window cleanup, and two new V3 proofs through the official CPU verifier. It measures two setup samples per mode as diagnostics only; these are not a statistically controlled throughput benchmark.

Only after every new preflight field passes does it open one 300-second live connection using the actual pool target, at most one fresh share, and no reconnect/retry. The report records shared-B windows and job B build/lease totals, alongside existing stage/search/share telemetry. No live speedup or pool acceptance is claimed before rig results.

Run `tools/run_v062.sh` with the published checksum-verified Python bootstrap. The launcher schedules a 15-minute fallback restart before temporarily stopping `pearl.service`, bounds installer execution to 780 seconds plus a 15-second termination grace, explicitly starts WildRig on exit and cancels the fallback only after WildRig is active. Existing CPU XMRig, clocks, pools, service definitions and autostart remain unchanged. No continuous custom miner is installed.

Validation: 96 targeted host tests passed, including real own-source CPU frontier equality and scripted pool/worker tests. GPU preflight, the official verifier proofs for this new allocation lifecycle, and the bounded live run must execute later on the rig. Host tests do not claim GPU hardware execution.
