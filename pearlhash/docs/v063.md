# v0.0.63: native warp XOR reduction experiment

This offline test replaces each five-shuffle XOR reduction in v060 shared-B scanning with one full-mask `redux.sync.xor.b32` instruction. The two per-tile reductions retain the same padding exclusion, 32-bit accumulator bits, rotation, transcript slot and candidate emission. The entire kernel body is identical apart from the fold helper name. The native instruction is emitted through volatile inline PTX before the lane-select branch. No tile geometry, MMA, B reconstruction, shared-memory layout, traversal, target, queue or guard change is included.

The readable sm_120 PTX includes the unchanged v060 scanner as its control. The candidate entry has two native XOR reduction instructions and ten fewer static shuffle instructions than that control, a 24-argument ABI and no CTA barriers. This is an instruction-count observation, not a measured speedup. Register usage, spills and elapsed performance must be checked on the rig.

Preflight compares four complete 4096-query transcript windows (first, odd row-pair crossing, odd middle and end), checks eight independent CPU samples, eighteen target/queue cases, a populated 67-query overflow, all 28 guard faults, a fresh candidate through a newly built V3 proof and the official CPU verifier, retained odd windows, and stale rejection/cleanup.

After preflight, the benchmark runs 24 alternating-order rounds of 65,536 tiles per mode, advancing in 4096-tile windows. Both modes use the same synthetic production job, nonce, target and exact tile ranges, with both caches resident in one CUDA context. Primary timings have no driver wrappers. Separate diagnostics enforce the existing 16 status resets, 32 kernel launches, 16 stream waits and 8064 downloaded bytes per mode. Report kernel resources alongside throughput. A candidate is preferred only after more than a 3% elapsed-time reduction. There is no automatic live integration.

The installer verifies the completed v060 and v061 gates and 30 existing dependency manifests. It does not depend on v062 being installed, started or complete. Its PYTHONPATH deliberately excludes v062, isolating the GPU instruction experiment from B-table ownership and live integration. Thus v062 and v063 can be run later in either order; both require the already completed v061 installation.

`tools/run_v063.sh` checks the pinned installer, schedules the 15-minute WildRig fallback before stopping `pearl.service`, bounds execution to 780 seconds plus 15 seconds termination grace, and explicitly restarts WildRig on exit. CPU XMRig, clocks, permanent services/autostart and pools remain unchanged. No pool connection, share submission or continuous custom miner is involved.

Development validation: 63 targeted host tests passed. NVRTC 12.9.86 builds reproduced byte-identical PTX. Source differential tests preserve every kernel operation except the intended reduction, exercise XOR algebra, and check the emitted ABI/instructions. Host lifecycle tests cover guard faults, canonical CPU-checked candidates and stale reset cleanup. GPU correctness, official-verifier proof execution for this candidate, and speed remain pending the rig run.
