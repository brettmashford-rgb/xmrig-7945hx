# V082: two-nonce B reconstruction reuse

V081 retained pair-direct: 2,326,001 tiles/s and approximately 84.20 W / 27,737 tiles/J. The 8x4 and 4x8 layouts lost throughput and efficiency. V082 starts architecture target 2 with an offline two-nonce experiment. No speedup or pool acceptance is claimed before rig evidence.

## What changes

For certificate V3, B's seed is derived from the job key and B commitment; A's seed also depends on the nonce-specific A commitment. Thus two distinct nonces for the same job can reuse B reconstruction, while A matrices, digest keys, candidates and proofs must remain independent.

| Mode | Threads/CTA | Nonces/CTA | Tiles/nonce/CTA | Total unique tiles/CTA | B fragment reconstructions/CTA | Static shared arrays |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| pair-direct | 256 | 1 | 32 | 32 | 1 | 10,240 B |
| twin-private-b | 512 | 2 | 32 | 64 | 2 | 14,336 B |
| twin-shared-b | 512 | 2 | 32 | 64 | 1 | 10,240 B |

The first eight warps handle nonce zero and the next eight handle nonce one. Each nonce retains the measured 16x2 axis layout, four tiles per warp, four K32 steps per stage, direct cached A loads, six MMA instructions and all 256 K128 checkpoints. No warp holds a second nonce's accumulators. The shared variant's first eight warps reconstruct B for both nonce groups. The private variant reconstructs separate B fragments for each group, with the same 512-thread geometry and shared initial B-uniform cache. This diagnostic distinguishes the effect of B-fragment reuse from changing the block shape. It is never the promoted production candidate.

Larger blocks can lose scheduling flexibility or residency, as earlier single-nonce block experiments demonstrated. Native registers, spills, shared memory and active blocks are reported. Equal per-thread work does not establish equal performance.

## Ownership and accounting

One guarded immutable B owner and one guarded immutable geometry owner serve both nonce searches through a bounded two-reader coordinator. The underlying owner remains leased until the last child releases it. Existing exclusive-owner behavior outside this experiment is unchanged. Each nonce retains its own fresh A seed, materialized A, digest key, target/status/queue/audit buffers, CPU reference profile and proof binding. Both cached A matrices occupy approximately 320 MiB in the production profile, in addition to B, maps and dispatch buffers.

The fused ABI extends the existing 24 arguments with nonce one's A pointer, digest key, status, candidates and audit output: 29 arguments total. B, maps, dimensions, first/count, generation and job target are shared and checked before fusion. The candidate never uses nonce zero's A or digest key for nonce one.

Each window scans at most 16,384 tiles per nonce, 32,768 unique tiles total. The unchanged paired traversal applies separately to each domain. Completed work is credited only after both results and all guards pass; neither duplicated scans nor overflow retries count as extra work. An explicit complete-queue retry repeats both lanes when either queue overflows. A stale job drains the owning stream and releases both children before shared inputs can be freed. The original pair-direct and guard-collector PTX entries remain byte-identical to V080.

## Fresh rig gates

Every mode must independently pass before timing. Two fresh production pairs, four distinct nonces, produce sixteen audited 16K transcript windows checked against independent V070 GPU results by canonical ID and 32 independent CPU transcript samples. Additional tests cover 48 lane-specific target/equality/overflow cases, both partial populated queues, both full 16K zero-capacity overflows, four invalid-axis requests, retained job inputs and changed nonce partners. A 160x234 odd-column profile covers six partial/boundary windows over both nonces and four CPU samples.

Two fresh synthetic V3 proofs, one per nonce, must pass the existing official CPU verifier. The digests must differ. Both domains' 28 guard endpoints are fault-tested (56 cases). Retained-buffer and stale-generation gates must also pass. These are offline proofs, not accepted pool shares.

## Speed and energy

Twelve balanced rounds cover every mode order twice. Each round scans the exact same 524,288 canonical tiles in each of the two nonce domains: 1,048,576 unique tiles per round, 12,582,912 unique timed tiles per mode. Setup and telemetry are excluded from speed timing. The candidate is preferred only if its median elapsed time is more than 3% lower than the two-nonce pair-direct control. The private variant is diagnostic only, even if faster.

The driver diagnostic requires 32 windows per nonce, 64 resets, 64 validated 504-byte guard/status readbacks, and no search uploads or context-wide synchronization. Pair-direct uses 128 launches and 64 waits; fused modes use 96 launches and 32 waits. Both per-nonce guard collectors are queued behind the scanner on one owning stream before its wait. Thus end-to-end gains can include reduced launch/wait overhead; shared-versus-private comparison holds this overhead constant.

Read-only NVML board-power sampling runs automatically at 200 ms. Each trial conditions one full nonce pair, then measures three fresh pairs including nonce preparation, A materialization, search and cleanup. Two balanced trials per mode measure twelve complete nonces, 100,663,296 unique tiles per mode. Initial per-job base/B/maps setup is excluded. Approximate GPU-board energy is not wall-plug energy. Unsupported sensors preserve speed results and explicitly mark energy unavailable. Activity percentages do not establish Tensor Core or bandwidth saturation.
