# v0.0.53: quad6/quad7 padding sweep against validated quad5

v052 rig preflight passed both four-row B kernels. Its balanced comparison
measured lean v051 621015.44, quad4 774883.80 and quad5 804823.59 tiles/s.
Quad5 won by 29.60% over lean, with 40 registers/thread and zero local bytes;
static shared memory was 20 KiB per CTA. Driver-call counts were identical.
These are synthetic search measurements; genuine pool acceptance remains unproven.

The user requested quad6 and quad7. b_stride_scan.cu includes the unchanged
v052 kernel body and instantiates only strides six and seven. All variants
still reconstruct four rows per packed word. Quad5 adds one padding word per
rank index, quad6 adds two and quad7 adds three. Their per-CTA shared memory
is respectively 20480, 24576 and 28672 bytes. More padding may improve bank
access patterns or reduce occupancy; a larger number does not imply more speed.
No A/B arithmetic, fragment mapping, MMA, transcript, hash, target, queue, nonce,
proof rule, kernel geometry or host lifecycle is changed. Both new entries
retain the 24-slot ABI and add no CTA barriers. Old entries remain available
in the same readable sm_120 PTX for the benchmark control.

Python selects quad5/6/7 only through an explicit integer stride selector.
It retains the established lean stream-reset/scalar-target path, all 28 guard
endpoints, complete-candidate independent CPU verification and stale/cursor
ownership. Existing sources and live-worker defaults are not modified.

Rig preflight compares each new stride against actual validated quad5 output:
four full 4096-query transcript windows per variant (first, row crossing,
middle, end), sixteen independent CPU samples, 36 target/queue cases, two
populated 67-query overflows, all 56 guard endpoints deliberately corrupted
with fresh dispatches, two fresh V3 proofs through the official CPU verifier,
retained odd miss windows and stale rejection. Successful preflight gates timing.

Three retained caches search one fresh synthetic production nonce/target and
identical ranges using advance(4096). Twenty-four rounds cover every permutation
of quad5/quad6/quad7 four times, 65536 tiles per mode per round. Setup cost and
driver-JIT register/shared/local memory use are reported separately. Primary
timings are uninstrumented. Separate diagnostics require all three modes to
retain 16 async resets, 32 launches, 16 stream waits and 16 readbacks (8064
bytes), with zero window host uploads/context-wide waits. Quad5 stays preferred
unless a new stride reduces elapsed time by more than 3%. Terminal labels:
STRIDE COMPARISON, DRIVER COUNTS, KERNEL RESOURCES. Full report:
b-stride-comparison.json. No live worker integration is performed here.

85 host tests pass, including 2048 new six/seven fragment mappings across all
lanes/K halves/column halves and offsets against the original cached_b_word;
24-slot PTX/no-barrier checks; strict selector validation; kernel selection,
lean driver behavior, stale cleanup/cursor protection; the existing exhaustive
packed-byte arithmetic and queue/guard/planning regressions; balanced same-range
comparison and installer proof/performance gates. GPU correctness, fresh proofs
and actual relative speeds remain pending until the rig run.
