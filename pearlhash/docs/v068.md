# v068: resolve A row addresses once per quartet

Offline comparison; v066 remains the validated live path. No live worker integration.

## Target and candidates

The actual compiled v066 K loop repeats five immutable A-axis map loads on every one of its 1,024 iterations. Its static loop contains 17 global-load instructions and 13 wide multiplies. Resolve the five live per-lane A-row addresses once after the existing complete input/domain/row/column guards, before the K loop.

The PTX retains the actual `four_tile_packed_scan` control. `hoisted_a_offset_scan` retains five compact 32-bit word bases and adds the K word offset: 12 global-load instructions and 11 wide multiplies in the compiled loop. `hoisted_a_pointer_scan` retains and advances five A pointers: 12 global-load instructions and five wide multiplies. Final pointer increments are suppressed to avoid forming beyond-one-past pointers for the last possible A row. Padding above packed row 39 contributes literal zero. These are static instruction counts, not memory transactions or a throughput prediction.

Both candidates preserve all six MMA operations, B reconstruction, accumulator checkpoints, XOR folding, target/queue handling and v066's complete concurrent four-transcript gather/hash/emission epilogue. ABI stays at 24 arguments. Resident geometry/B ownership, fresh A and nonce bindings, canonical traversal, stream, launch dimensions and all guards are unchanged. There are no new CTA barriers, buffers, uploads or host readbacks. Register counts, spills and throughput need rig measurement. v067's sequential epilogues were 8.6%/9.6% slower despite using 64 versus 96 registers; neither is used here.

Separate driver diagnostics enforce the same reset, launch, wait and readback contract. Prefer a candidate only with more than 3% median elapsed reduction over control. This measures search, not whole-miner speedup or pool acceptance.
