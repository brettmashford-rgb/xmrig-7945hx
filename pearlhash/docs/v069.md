# v069: packed eight-tile B reuse

Offline comparison against the rig-validated v068 advancing-pointer kernel. v066 remains the last validated live worker; no live integration here.

## Opportunity and candidates

Four v068 tiles pack 40 A rows into three 16-row tensor slabs, reconstructing B once for those four tiles. Pack eight tiles' 80 A rows into five slabs instead of six for two quartets. This reduces tensor instructions from 12 to 10 per eight tiles (16.7%) and shares one B reconstruction across eight rather than four tiles. These are work-count changes, not measured throughput gains. Ten once-resolved A pointers preserve v068's address optimization. Final pointer increments are suppressed, including the final physical A row. Shared B storage stays 24,576 bytes per CTA, ABI 24 slots, one stream and 256-thread CTAs.

`hoisted_a_pointer_scan` is the unchanged actual v068 control. `eight_tile_packed_scan` gathers all eight transcripts before emission. `eight_tile_serial_scan` gathers/hashes/emits one at a time, with full-warp reconvergence after lane-zero emission. The serial epilogue lost on four tiles in v067; it is tested again here because eight transcripts and five accumulator slabs change register pressure. Neither candidate is preferred before rig resource/correctness/timing results. Do not assume fewer matrix instructions means a speedup.

## Canonical correctness

Octet ordinal maps to row `8*((ordinal/8)/columns)+(ordinal&7)` and column `(ordinal/8)%columns`. All 8,388,608 production canonical tiles remain exactly once. GPU input guards require row-axis count divisible by eight and validate every one of the 80 selected A rows and 16 B columns before addressing. Active masks and a grid rounded for the first partial octet restrict output to the exact requested interval, including one-query and odd windows. Each canonical transcript owns exactly ten real A rows across the five slabs. EightSearch remaps returned hit IDs once before unchanged independent CPU candidate checking/proof construction.

A full transcript window is compared by canonical tile ID against real v068 dispatches, sorting/grouping contiguous control ordinals and restoring the requested octet order. Direct array comparison between the two traversal orders would be invalid. Each new mode performs a full production bijection, two production nonces/eight 4,096-query windows, 16 independent CPU transcript samples, 18 target/queue cases, 67-query populated overflow, 28 guard corruptions, geometry/B reuse and odd/stale lifecycle rejection. Two fresh V3 proofs per mode pass the installed official CPU verifier before timing. Proofs/captures/seeds stay private on the rig.

## Fair measurement

All modes search 131,072 tiles per round, a whole eight-row-axis group with 16,384 column axes. This gives exactly the same canonical tile set for the quartet and octet traversals. Warmup and 24 rounds cover balanced six-order permutations, using advance(4096). Unique timed work is 3,145,728 tiles per mode. Initial setup/JIT and nonce/commitment preparation are excluded and setup reported separately; all three A caches and independent exclusive B/geometry owners remain resident in one CUDA context. Primary wall timing is uninstrumented. Separate diagnostic round enforces 32 stream resets, 64 launches (scanner + guard snapshot), 32 waits, 32 readbacks/16,128 bytes and zero HtoD/context waits during search. Compiled registers/shared/local resources are reported. Prefer a candidate only if median elapsed reduction exceeds 3% over v068. GPU search throughput is distinct from whole-miner or pool-acceptance evidence.
