# v079: reuse A operands across two column groups

V078 retained wide16k. Larger blocks lost throughput, larger dispatches gained under 2% while losing efficiency, and V077's register residency requests introduced local memory and substantial slowdowns. V079 tests sharing loaded A operands, without increasing the four tiles' accumulator/transcript state held by each consumer warp.

| Mode | Kernel | Block layout | A operand source | Static shared arrays |
| --- | --- | --- | --- | ---: |
| wide16k | cta_b8_scan | 32 row axes x 1 column axis, 8 consumer warps | Original direct loads | 7,168 bytes |
| pair-direct | a_pair_direct_scan | 16 row axes x 2 column axes, 8 consumer warps | Matched direct loads | 10,240 bytes |
| pair-shared-a | a_pair_shared_scan | Same paired layout | Four producer warps stage A for paired consumers | 30,720 bytes |

All modes use 256 threads and guarded 16K dispatches. The original control is included unchanged; its compiled PTX entry and guard collector match v075 byte for byte. The paired direct/shared variants instantiate the same device template, with a compile-time switch for A staging. The matched direct control isolates the effects of the changed two-column geometry from the A-sharing change. Promotion is always against the real wide16k baseline, rather than against a potentially slower matched control. Shared/direct incremental speed is reported separately.

## Device work

Consumer warp pairs handle the same quartet of row axes for two separate column axes. The even warp loads ten A words per lane into a four-K32-stage shared array; both warps consume those exact words. The producer remains active even if a partial query window requests only the second column and none of its own column's outputs. Missing row quartets and an odd final column are guarded. The last unpaired column never reads a nonexistent B map. Every warp reaches each block barrier.

The matched variants stage four K32 steps (K128) at a time. Both build two B fragment sets with the same work; consumers retain independent accumulators/transcripts per column. The source retains all six MMA instructions per K32 step, the original accumulator order, exact K128 cumulative checkpoints, fold, hash/target/candidate emission and A input bounds. The direct mode advances A pointers after K32 steps; the shared producer advances after its K128 group. Final pointer advancement is suppressed in both paths.

At a full paired block, staged A uses 1,310,720 global word loads versus 2,621,440 direct word loads over K32768, with both consumers reading the shared words. This halves logical global A operand loads. It does not establish a halving of physical DRAM traffic: cache hits, shared writes/reads, register allocation, barriers and the changed B reuse can offset the savings. The paired layout shares B across sixteen rather than thirty-two row tiles per column and has four rather than eight K steps per stage. Those geometry/staging costs are visible in pair-direct versus wide16k. No gain is assumed.

## Correctness before timing

Each of the three modes independently checks two fresh production nonces, eight 16K transcript windows reordered by canonical tile ID against v070, sixteen CPU transcript samples, exact target cases, populated partial overflow, full-16K zero-capacity overflow, all 28 allocation-guard endpoints, invalid row/column maps, retained/stale ownership and two fresh V3 proofs checked by the official CPU verifier.

Each mode also runs a separate small 160x110 profile with sixteen row axes and three column axes. A CPU-prepared constant B commitment avoids introducing a different GPU commitment path into this edge test. Six audited windows include first-column/second-column boundaries, a second-column-only request, the final unpaired column and the last query. All 48 transcripts match v070 by canonical ID, and two samples match independent CPU matrix math. These odd-column checks are mandatory installer gates.

Compiled C++ helpers run under undefined-behaviour sanitizer. Tests exhaust all 8,388,608 production canonical IDs, inverse mapping and whole-window work-set equality. They cover odd column dimensions and partial emission masks, all 5,120 A-stage word locations and 1,024 B-stage word locations, and all K positions with nonmonotone maps including the final physical A row. The simulated paired consumers receive exactly the direct operands; producer load count is half their combined read count. Source contracts require the MMA/fold/emission code to be unchanged after substituting staged operands. PTX checks the real ABI, MMA count, barriers and shared array sizes.

## Speed and energy

Twelve speed rounds use all six mode orders twice. Each mode processes the identical canonical set of 524,288 tiles per round, aligned to a full 32-row-axis production group; this equals two complete paired row groups. Setup and telemetry are excluded and setup is separately reported. Warmup, 6,291,456 unique timed tiles per mode and the separate driver diagnostic fit within one nonce. The diagnostic requires 32 resets/waits/504-byte readbacks, 64 scanner/collector launches and no HtoD/context-wide synchronization for each mode. A candidate is preferred only if median elapsed time is more than 3% lower than wide16k.

The unchanged read-only NVML energy phase samples every 200 ms in two balanced rounds, with one conditioning nonce and three measured full nonces per trial, 50,331,648 measured tiles per mode. It includes fresh nonce/A preparation, search and cleanup but excludes initial job/base/B/geometry preparation. Unsupported sensors mark energy unavailable without invalidating speed results. Board energy is approximate and is not wall-plug power or live-pool efficiency. Activity percentages do not establish Tensor Core saturation, bandwidth saturation or achieved occupancy.
