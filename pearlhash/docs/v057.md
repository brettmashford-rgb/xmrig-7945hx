# v0.0.57: reduce B fragment shuffle work

v056 early A/B alone passed correctness/proof checks but measured 772505.25
versus quad5 812715.84 tiles/s (-4.95%). It used 48 registers per thread
versus quad5's 40, with no local spill. v054 quad5 remains the live path.

This offline experiment changes B fragment arrangement instead of grouping
or carrying future operands. The original quad5 loop reconstructs four
packed B words per producer and uses four gather shuffles per output word:
sixteen B shuffles per inner iteration. b_quad_transpose_scan permutes the
producer K indices, then uses two butterfly shuffle/byte-permutation stages
per output word, reducing that portion to eight shuffles. Two byte-permutation
instructions per word replace byte extraction/assembly. The hardware benefit
is unproven until timed; this is an instruction tradeoff, not a speed claim.

b_transpose_index exchanges the two low pairs of lane bits. Within each
half-warp, K-byte index bits now occupy lane bits 2 and 3. Stage one exchanges
lane bit 2 with byte-position bit 0, using XOR-4 shuffle and selectors
0x6240/0x3715. Stage two exchanges lane bit 3 with byte-position bit 1, using
XOR-8 and selectors 0x5410/0x3276. Every lane receives exactly the original
four B bytes in the original order. The lane permutation reads the same
pair index set and uses unchanged modulo-256 B arithmetic.

The kernel includes unchanged quad5 control entries. It retains stride-five
shared storage (20480 bytes per CTA), 256 threads/eight query warps, original
32-K iteration, 24-slot ABI and no CTA barriers. A loads, MMA accumulation,
transcript folding and final hash/target/queue tail remain verbatim quad5.
All host guards, stream ordering, independent CPU candidate verification,
resumable cursor and stale lifecycle remain unchanged. PTX has 37 total
static shuffle instructions for the control and 29 for the new entry; its
B redistribution contributes sixteen versus eight. Actual JIT resources are
reported outside timing. The live worker is not modified.

Host math checks compile the actual new index/selector helpers and existing
B arithmetic, emulate the two simultaneous warp exchanges, and compare all
32 lanes, both halves and both column blocks at every one of the 1024 K
steps for two independent datasets: 262144 exact comparisons against the
original cached_b_word. Source-tail and PTX/ABI checks complement the GPU
preflight; host tests do not replace hardware verification.

Before timing, check_b_transpose_job.py requires four full 4096-query transcript
windows against actual quad5 (first, row crossing, middle, end), eight CPU
transcript samples, eighteen target/queue cases, a populated 67-query overflow,
all 28 deliberate guard faults, a new V3 proof passed by the installed official
CPU verifier, retained odd miss windows, stale rejection and leak-free cleanup.
Any missing/failed gate blocks the benchmark.

The paired benchmark uses one shared synthetic production nonce/target and
identical intervals, both caches resident, 24 alternating-order rounds of
65536 unique tiles per mode, advance(4096). Primary timing is uninstrumented.
A separate diagnostic requires sixteen stream resets, 32 launches, sixteen
stream waits and sixteen 504-byte downloads (8064 bytes), zero uploads and
zero context synchronizations. A candidate needs more than 3% median elapsed
time reduction to be preferred; there is no automatic live integration.
