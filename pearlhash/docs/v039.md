# v0.0.39: GPU constant B commitments before nonce scanning

The v38 rig preflight matched all descriptor bytes and first/middle/end GPU
transcripts, then its fresh V3 proof passed the official offline CPU verifier.
The five-minute live run searched 48,607,232 tiles versus v36's 7,806,976 (about
6.2 times more completed work), with four complete nonces versus zero. It started
seven nonces across three jobs. No custom share was attempted or sent. Status
report ACKs remain separate from share acceptance.

CPU B commitment preparation still consumed 87.020 seconds, versus 204.931 seconds
of search. This release adds a separate constant-matrix commitment module. It
synthesizes keyed full 1024-byte chunks on GPU without allocating the 8 GiB matrix,
then folds CVs in two ping-pong buffers. At 8,388,608 leaves these occupy
402,653,248 bytes including guards (384 MiB plus 64 bytes). Interior CV storage is
not uploaded or downloaded wholesale. Only keys, an optional 16-byte tail, guards,
sampled leaf CVs, root and required sparse sibling CVs cross the PCIe boundary.

The independent compression core handles keyed chunk start/end flags, global
64-bit leaf counters, final-tail bytes, parent flags and root output flags. Odd
nodes promote unchanged until a real parent pair is present. Host tests compile
the exact GPU header as C++ and compare it with the existing independent CPU
library across fills, keys, counter boundaries, tail/root flags and parent roots.
A fake-driver tree harness compares complete sparse openings for single, odd and
power-of-two trees, and tests guards, input caps and cancellation cleanup.
These are host checks, not a claim that the new kernel has passed on a GPU.

Every returned opening is independently checked using CPU chunk/parent primitives.
Three sampled GPU leaf CVs are also CPU checked on every construction. The base
helper creates, uses and closes a temporary GPU context on the search worker
thread before its tile-scanning context starts. No commitment allocation survives
into scanning. Current-job checks surround construction and every synchronized
fold level. Failed/stale construction cannot publish a base to the nonce stage.

The existing CPU commitment implementation remains available. The bounded worker
selects GPU B construction only with an explicit --commitment-module option; the
new installer supplies it. Root/key/config binding, nonce derivation, scan kernel,
validated-axis planner, target, proof encoding and submission gates are unchanged.
Candidate proof openings still use the established CPU builder. XMRig stays
running; no CPU configuration, clocks or service definitions are changed.

Mandatory rig preflight checks eighteen small GPU cases against independent CPU
roots and complete opening bytes. It then builds one fresh full production CPU
reference, compares the exact GPU root/opening, and reports both timings including
GPU setup/allocation/folds/opening checks. A fresh synthetic job with a GPU-built
B root must produce a new V3 proof accepted by the existing official offline CPU
verifier. Only then does one five-minute actual-target live run begin, with at
most one fresh custom share and no reconnect or automatic retry.

The distribution contains independent readable CUDA/Python sources and actual
sm_120 PTX built with NVRTC 12.9.86. A repeat build must be byte-identical. No
vendor compiler library or new native CPU binary is distributed or installed on
the rig. Existing scan/runtime sources, PTX and local CPU library are verified.
The shell stops/restores WildRig with a 15-minute fallback; autostart is preserved.
GPU correctness, full commitment speed and live improvement remain pending the
rig run. A successful offline proof does not establish pool share acceptance.
