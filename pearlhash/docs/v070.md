# v070: cooperative B reconstruction across independent quartet warps

Offline experiment against v068's advancing-pointer kernel. v066 remains the last validated live path. v069's larger octets lost: 1,286,676 and 1,473,251 tiles/s versus 1,567,481 for the quartet control, with 168 and 95 registers versus 96. Both are rejected.

## Opportunity

Eight warps now retain eight independent v068 quartet accumulator/transcript sets while sharing a column axis. Rather than rebuilding identical B fragments eight times, each warp produces a different K step into a block-owned fragment buffer. All warps then consume those fragments for their own A rows. On full production blocks this removes seven of eight B reconstructions; it does not remove seven of eight whole-kernel instructions or predict an eightfold speedup.

The 8-step and 16-step variants amortize two block fences over each 8/16 K steps. The unchanged stride-six uniform cache is stored once per CTA rather than once per warp. Compiled static shared arrays total 7,168 and 11,264 bytes, versus the control's 24,576. Each query quartet still has three accumulator slabs, six MMA instructions per K step, five advancing A pointers, four prefix folds and the exact v068 concurrent gather/hash/emission epilogue. Actual registers, occupancy and timing require rig measurements. Barriers, additional shared loads and changed A locality may erase the reconstruction savings.

## Coverage and synchronization

A CTA handles 32 consecutive row axes for one column axis. The traversal is an explicit bijection with an inverse and canonical Hit remapping. Fixtures with up to 32 row axes use their actual multiple-of-four row count. Larger row counts must be divisible by 32. The kernel validates all present quartet maps before any A addressing, using a block-wide OR reduction. Invalid input therefore exits uniformly. Even warps with no requested output remain B producers and participate in every block barrier. Inactive consumers never form A pointers. Buffer reuse has a fence after consumption; the final A increment remains suppressed.

Fresh correctness checks compare all transcript words against the actual v068 control by canonical tile ID, restoring the changed order. Per variant: two production nonces, eight 4,096-query windows including a 32-row boundary, 16 independent CPU samples, 18 target/queue cases, populated 67-query overflow, five invalid row/column-map cases exercising sparse CTA participation, 28 allocation-guard faults, retained odd windows and stale rejection. Two newly constructed V3 proofs must pass the official CPU verifier before timing. No real pool connection or share submission occurs.

## Measurement

Each timing round covers 524,288 tiles: exactly one complete 32-row-axis group at 16,384 column axes, giving identical canonical work for every mode. Twelve balanced rounds cover the six permutations twice; warmup, timing and diagnostic ranges fit within one 8,388,608-tile nonce. There are 6,291,456 unique timed tiles per mode. A 24-round schedule at this window size would exceed the nonce and is deliberately rejected by a host test.

All paths retain their independent A, B and geometry owners in one context. Setup/JIT is excluded from primary search wall time and reported separately. Each 4,096-tile advance preserves the existing reset, scanner, guard snapshot and readback contract. Separate diagnostics require 128 resets, 256 launches, 128 stream waits, 128 readbacks/64,512 bytes, zero search-time HtoD and no context-wide waits per mode. Prefer a candidate only after greater than 3% median elapsed reduction over the actual v068 control. Kernel throughput is not whole-miner performance or pool-acceptance evidence.
