# v0.0.65: retain search geometry across fresh nonces

The validated v062 path rebuilds the immutable FastPlan and uploads its 512 row axes plus 16384 column axes for every nonce. This offline experiment compares actual v062 against retaining the CPU plan, and against retaining both plan and GPU axes. All modes use the same v060 GPU scanner and v062 job-owned B tables. No new PTX or native archive is needed; reuse the installed verified readable v060 PTX. v063/v064 completion is not required.

JobGeometry binds its validated plan to job key, certificate version, dimensions and both encoded patterns, and binds GPU buffers to the CUDA device. A nonce acquires an exclusive lease. Wrong job/profile/device, stale work, overlapping leases and closing an owner while leased are rejected. Per-nonce A noise, seeds, tail, materialized A, target buffer, descriptor/queue/snapshot buffers and generation remain fresh. Changed-target notifications reuse only matching immutable geometry. New map allocations are recorded before uploads so constructor failure cleans up owned memory.

ResidentDispatch optionally borrows the two axes buffers. Borrowed buffers remain in the same snapshot/guard list but are absent from its allocation ownership list. Thus all 28 guard endpoints, canonical CPU checking of complete returned candidates, overflow handling and the status-only scan protocol remain intact. Closing a nonce drains work and releases its geometry/B leases; only the job owner frees shared maps. The default v062 construction path is preserved as the benchmark control.

Preflight uses two distinct production nonces. It compares eight full 4096-query windows across both cached modes against actual v062, checks sixteen independent CPU transcript samples, verifies every uploaded map byte, and checks thirty-six target/queue cases plus two populated 67-query overflows. It then creates two fresh V3 proofs through the official CPU verifier, changes target/generation, checks retained odd windows and stale cleanup, and injects all 28 guard faults in each cached mode. Correctness/lifecycle fields must pass before timing.

The benchmark measures 24 fresh nonce cycles per mode in all six balanced orders. Each cycle includes construction, 65536 search tiles in 4096-tile windows, and cleanup. The same fresh context and canonical ranges are used for all three modes within each round. One-time geometry build/upload cost is charged to each cached mode. Shared B/base/frontier preparation is excluded equally. Phase medians separate setup, search and cleanup; this short-cycle result is not a full-nonce or whole-miner speedup claim.

Primary timing is not wrapped by driver counters. Separate diagnostics require the unchanged 16 resets, 32 launches, 16 waits and 8064 downloaded bytes per search window sequence. Setup diagnostics verify exactly two fewer map allocations/initializations and two fewer payload uploads. Production map payload is 2162688 bytes; existing guarded initialization plus payload upload means 4325440 fewer uploaded bytes per reused nonce. Extra owner guard reads at setup remain included in timings and diagnostics. Both target and queue initialization remain per nonce.

The installer verifies 31 dependency manifests, the completed v060/v061 gates, v062 fresh proof checks and its successful joined live report. The CPU library hash is read from the installed verified v031 manifest. No wallet, capture, header, nonce, seed or proof is published. The launcher schedules a 15-minute WildRig fallback before stopping it, limits execution to 780 seconds plus 15 seconds termination grace, and explicitly starts WildRig on exit. CPU XMRig, clocks, pools, permanent services/autostart remain preserved. No pool connection, share submission or continuous custom miner is installed.

Development validation: 127 targeted host tests passed, including two cache modes, all guard endpoints, fresh A/target rebinding, wrong-pattern/job/device rejection, stale reset/launch cleanup, complete overflow retry/CPU/canonical checks, partial-construction failures and existing worker/submission regressions. A fully scripted benchmark also executes real host allocation/upload accounting and the same snapshot protocol. Rig GPU preflight, official verifier execution for this ownership path and timing remain pending.
