# v0.0.59: revisit the small stride-six gain on v057 transpose

The user asked to revisit earlier gains below the adoption margin. The two
likely examples were v047 direct-map scanning (+1.45%) and v053 stride six
(+2.13%). Direct-map scanning was subsequently included in the packed-direct
path and remains part of v057. The v050 stream-reset-only gain (+0.79%) is
also already included through lean dispatch. These cannot be added again.
Stride six remains unused and is worth retesting after the v057 shuffle change.

v057 is the current validated offline baseline. v058 biased B arithmetic was
correct but effectively tied/slightly slower (859126.95 versus 860280.00
tiles/s, -0.13%). v059 retains original general B arithmetic, v057 producer
mapping and two-stage byte transpose; it does not include biased arithmetic,
grouping or early operand carrying. v054 remains the last live-validated path.

The new b_quad_transpose6_scan entry differs from v057 only in shared-cache
padding/address stride: six words per rank index instead of five. Cache
payload is still four words (sixteen B rows); extra words are padding, not
additional rows or mathematical work. Shared memory rises from 20480 to
24576 bytes per CTA. The tradeoff between shared access costs, scheduling and
residency must be measured again; no improvement is assumed.

The new readable PTX includes the unchanged v057 entry for the control.
It keeps 256 threads/eight query warps, original 32-K iteration and 24-slot
ABI. A loads, MMA order, transcript fold and hash/target/queue tail are
verbatim. Transpose helpers/selectors and general modulo-byte B arithmetic
are unchanged. No new allocations, CTA barriers, host readbacks or resets.
All guards, independent CPU candidate verification, overflow handling and
stale/cursor lifecycle remain intact. No live worker integration occurs.

Host math checks compare all 32 lanes, all 1024 K steps, both halves and
both column blocks on two int8 datasets (262144 exact comparisons), compiling
actual index/selector and B arithmetic helpers at stride six. Tests also
cover unchanged source tail, new ABI/MMA/shuffle count, actual v057 control
selection, stream/reset/readback behavior, stale cleanup and no cursor credit,
paired interval/order/timing selection and installer proof/completion gates.
92 targeted host tests pass and repeat PTX builds are byte-identical.
The GPU preflight remains required, independent of host tests.

Before timing, four full 4096-query windows compare against v057 (first,
row crossing, middle, end), eight independent CPU transcript samples,
eighteen target/queue cases, populated 67-query overflow, all 28 deliberate
guard faults, a fresh candidate/V3 proof through the installed official CPU
verifier, retained odd miss windows, stale rejection and leak-free cleanup.
Any failed or incomplete gate prevents the benchmark.

One synthetic production nonce/target is shared by both retained caches.
Twenty-four alternating-order rounds search identical 65536-tile ranges
per mode using advance(4096). Primary timing is uninstrumented. A separate
diagnostic requires sixteen stream resets, 32 launches, sixteen stream waits,
sixteen 504-byte downloads (8064 bytes), zero host uploads/context waits.
Setup and JIT resources are separate. A candidate must reduce median elapsed
time by more than 3% to be preferred. Output: TRANSPOSE SIX COMPARISON,
DRIVER COUNTS, KERNEL RESOURCES, transpose-six-comparison.json. Gains are
relative to v057, not the earlier v052 kernel.

The installer verifies 27 dependency packages, the completed v058 experiment,
the v057 winning comparison and existing correctness/lifecycle gates. Old
GPU tests are reused rather than repeated. CPU library hash comes from
installed verified v031 metadata. No toolkit or pip package is installed.
Actual GPU correctness and speed for the new entry remain pending rig run.
No pool connection, shares, fee or live worker change. Genuine independent
pool acceptance remains unproven. No private wallet, capture, header, nonce,
seed or proof is published. All miner code is our own. CPU XMRig, clocks,
pools, permanent services and autostart are preserved. The launcher schedules
a 15-minute WildRig fallback before stopping pearl.service and explicitly
restarts it on exit. No continuous custom miner is installed.
