# v0.0.54: bounded live quad5 integration

The v052 RTX 5060 offline comparison measured 804823.59 tiles/s for quad5
versus 621015.44 for lean v051: 29.60% more controlled search throughput.
Both candidate layouts passed full transcript, CPU sample, target/queue,
guard fault and fresh V3 official CPU verifier checks before benchmarking.
The subsequent v053 stride sweep measured quad5 802325.05, quad6 819388.36
and quad7 760063.63 tiles/s. Quad6's 2.13% gain did not clear the required
3% elapsed-time reduction. Quad5 remains selected. These controlled timings
are not live throughput or accepted shares.

This release adds --quad5 to mine_bounded.py. It selects the already tested
new_b_quad_search(...,padded=True), BQuadPaddedDispatch and the unchanged
v052 readable PTX entry b_quad_padded_scan. One stream, 4096-tile windows,
stream-ordered status reset, packed status plus all guards, uniform target
validation and independent CPU candidate verification are retained. No new
kernel compilation or toolkit installation is needed on the rig. Existing
scanner modes remain available; --cache-a is required and scanner choices
are mutually exclusive. No nonce, target, proof or pool protocol change.

The pinned installer verifies 21 installed dependency manifests and files,
including v052 source/PTX, and reads the CPU library hash from verified v031
metadata. It requires completed v052 offline preflight with two official
CPU verifier proofs, eight full transcript windows, sixteen independent CPU
samples, 36 target/queue cases, 56 guard faults, populated partial queues,
retained windows and stale rejection. It also requires a completed balanced
24-round comparison, finite quad5 improvement above the adoption threshold,
quad5 preference and exact measured driver calls/bytes. Missing or failed
gates prevent downloads and the live connection; old GPU tests are reused.

The worker opens one pool connection for at most 300 seconds and submits at
most one fresh independently checked candidate. Heartbeats run every 15
seconds, with nonce and cursor progress. No reconnect or share retry.
The report mining-result.json records scan_backend quad5-one-stream-v054,
work/nonce counts, stage timing, backend lifecycle, joined worker state and
separate share/report counters. Terminal output adds Quad5 windows.
Assigned extranonce as worker nonce remains a hypothesis until a genuine
custom share is accepted. Status acknowledgements never prove acceptance.
v054 GPU/live execution remains pending on the rig.

Host tests cover quad5 selection with padded=True, full-nonce rollover,
scripted proof/submission/correlated verdict, status acknowledgement without
submission, joined cleanup, incompatible flags before networking, installer
proof/guard/performance/driver gates and the established backend, queue,
nonce, receiver and submission lifecycle. Scripted GPU/proof data do not
establish genuine pool acceptance.

The saved login is located locally by the existing find_login helper.
No wallet, captured job, nonce, seed or proof is published. This release uses
our own miner sources, with no developer fee or copied third-party miner.
CPU XMRig, clocks, pool configuration, permanent service definitions and
autostart are preserved. The launch wrapper schedules a 15-minute fallback
before stopping pearl.service and explicitly restarts WildRig on exit.
No continuous custom miner is installed.
