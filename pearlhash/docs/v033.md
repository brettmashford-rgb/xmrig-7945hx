# v0.0.33 cooperative tile experiment

New independent kernel: 256-thread blocks compute sixteen existing search tiles
as a 2-A by 8-B cross-product. Each warp computes two tiles, retaining their
separate rank-prefix folds, transcripts, keyed digests and candidate targets.

All warps share 20 A rows and 128 B rows per K128 step. Two 18.5-KiB shared
stages use aligned 16-byte `cp.async` copies; the next step loads while the
current one computes. Block barriers protect stage reuse; collective descriptor
validation makes early rejection block-uniform. Padding remains zero, and no
whole-matrix allocation is introduced. Materialized inputs are K-major fragments
in first-use row order, capped at 128 MiB.

A cooperative batch must contain complete ordered 2-by-8 blocks. Host validation
rejects malformed or partial groups before launching collective GPU code. The
kernel also checks descriptor bounds and cross-product structure. A cache keeps
one immutable row map while benchmark modes select either isolated-fragment or
cooperative compute on the same bytes. The old virtual path remains the control.

The NEW kernel gets eighteen independent CPU transcript/digest/queue scenarios
across boundary/tail, production endpoints and reversed/tail-extreme inputs. The
4096-query production-shaped comparison uses rotating path order for eight
rounds; six outputs in distant blocks independently match CPU math. All three
full transcript sets must agree before timings run. Setup cost and setup-inclusive
cooperative time are reported. This is repeated synthetic component work, not
unique mining throughput or a pool verdict.

Seven Python host tests and the compiled fragment-layout check passed. Actual
NVRTC 12.9.86 compilation emitted readable sm_120 PTX; byte-identical rebuild is
recorded. Build helper block barriers remain forbidden by default, with an
explicit allowance only for the new cooperative CTA build. No compiler is
installed on the rig. GPU correctness and speed remain pending.

This experiment incorporates general shared-tiling and pipelining lessons from
the public source review; no external miner implementation was copied. It is
not connected to live mining until validation and timing justify that change.
