# v0.0.45: one-stream resident axes and GPU descriptor construction

After v044 fixed paired queue traffic, its controlled rig comparison still
preferred one stream: 360863 versus 330330 tiles/s. This release targets the
one-stream path's per-window CPU serialization and 1.2 MiB descriptor/target
upload. It does not increase stream count or alter mining math.

Upload canonical validated FastPlan row and column axes once per nonce, each
axis entry retaining its existing 32-u32 global indices/padding. At production
size the axes occupy (512+16384)*128 = 2162688 bytes. Upload the nonce's uniform
4096-entry target buffer once. Each window prepares only lazy queries and bounds
for CPU candidate checking, uploads an 8-byte status reset, then launches a small
GPU descriptor builder followed by the validated cached-A scanner on one stream.
No host wait occurs between those launches. Builder receives axes, axis counts,
start tile, count and output pointer; it maps row-major IDs with quotient and
remainder and emits the identical 66-u32 descriptors. Start/count limits are
checked on host and GPU. Both dispatch and axes guards remain checked.

Tile math comes from the unchanged cached_a_tile_scan.cu include. No new MMA,
hash, target, V3 seed, nonce or proof rule. A new readable sm120 PTX bundles both
the existing scan/materializer entries and the descriptor builder. NVRTC12.9.86,
compute120/c++17; repeat builds are byte-identical. No toolkit required on rig.

The backend preserves NonceSearch range/cursor/candidate mapping and full-queue
retry behavior, retains buffers per nonce, uses compact populated-only queue
readback and independently checks returned complete candidates on CPU. Stale
checks run before builder, before scanner and after GPU/CPU checks. In-flight
builder/scanner are synchronized before freeing nonce data. Constant targets
cannot change within a backend; a new job/target requires a new backend.

New rig preflight compares four full 4096-query descriptor/transcript windows
(first, canonical column-to-row crossing, middle, end) against CPU serialization
and validated v040 GPU output, with eight independent CPU transcript samples.
Checks eighteen single-query CPU target/queue cases at first/middle/last IDs,
a populated overflowing 67-query queue, fresh synthetic resident candidate ->
new V3 proof -> official CPU verifier, retained odd miss windows and stale reject.
Only a complete preflight enables timing. No old commitment test suite repeated.

Twenty alternating-order rounds compare baseline cached-A versus resident maps
on the same fresh synthetic production nonce and 65536 IDs per round. Both use
advance(4096). Context/JIT, common commitment and nonce preparation excluded;
search/cache setup reported separately. Primary timings are uninstrumented;
separate equal-range driver diagnostics count calls/bytes. Resident axes/target
setup traffic is outside per-window diagnostics and reported as setup cost.

No pool connection or live miner selection; performance remains unmeasured until
the rig run. This is not a mining rate/acceptance/power/bandwidth-saturation claim.
Installer verifies completed v044 and pinned installed dependency files/library,
installs own source/PTX into v045, and runs the new gate then offline comparison.
The Termius wrapper temporarily pauses/restores WildRig with a 15-minute fallback;
XMRig, clocks and service definitions remain unchanged.
