## Automatic power and activity monitoring

No second terminal, pip package, profiler install or clock/power change is needed. After speed timing, the same launcher performs separate sustained energy trials. A read-only ctypes NVML client binds to the active CUDA device's PCI address, avoiding assumptions about CUDA/NVML index ordering. It samples board power every 200 ms along with GPU kernel-active percentage, memory-active percentage, SM and memory clocks, temperature, power limit, P-state and clock-limiting reason bits when supported.

There are two balanced rounds (forward and reverse mode order). Every trial first conditions its mode with one complete nonce, then measures three complete production nonces. All modes use the same three nonce values and full canonical domains within a round. Measurement includes fresh nonce preparation, A setup, all 8,388,608 search tiles per nonce and nonce cleanup. Initial per-job base/commitment frontier/B/geometry preparation is excluded. Thus each mode's energy estimate covers 50,331,648 measured tiles across six complete nonces, separately from the primary speed timings.

Power is integrated with the trapezoidal rule using monotonic timestamps at reading midpoints. Raw timestamps/read durations and samples remain in combo-comparison.json. Energy and tiles/joule are withheld for windows shorter than five seconds, sample gaps exceeding one second, or invalid/unavailable power. Optional unsupported activity/clock metrics remain null. Unsupported NVML or power sensors leave the speed result usable and explicitly mark efficiency unavailable. Actual scan errors still fail the comparison. Sampler threads and NVML handles close on success or failure.

These are approximate GPU-board energy estimates, not wall-plug power or CPU/system efficiency. GPU activity means time with a kernel executing; memory activity is time doing device memory reads/writes. Neither establishes Tensor Core saturation, memory bandwidth saturation or achieved SM occupancy. Short sampled clock-limit flags are time-weighted observations, not hardware violation counters. No offline tiles/joule result is directly comparable to another miner's H/s/W.

## Running

The installer verifies the existing immutable v074 package, completed suite and the Small4/wide16k promotion margins, plus the established older dependencies. It installs to /home/user/pearlhash-dev-v0.0.75. One checksum-pinned run_v075.sh command runs all gates, speed tests and power trials, then restores WildRig. A 1,500-second deadline and thirty-minute recovery timer bound the run. CPU mining, pools, clock settings, permanent service definitions and autostart are unchanged. There is no pool connection or submitted share.

Send COMBO RESULT, POWER RESULT and KERNEL RESOURCES. The full report is combo-comparison.json and the console log is /home/user/pearlhash-v075-launch.log.
